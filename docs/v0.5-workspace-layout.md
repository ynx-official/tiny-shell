# V0.5：工作区布局重构

## 目标

让应用具备两种核心界面：连接前的“概览首页”，以及连接后的“终端工作区”。本次重构不改变既有 SSH、终端、分屏和 SFTP 的业务逻辑，只重新组织页面入口、侧栏和工作区尺寸。

## 第一阶段：框架与状态

- [x] 提供概览、连接管理器和密钥管理器页面。
- [x] 提供命令管理器和独立设置页面。
- [x] 连接前使用全局导航侧栏；连接后切换为会话信息侧栏。
- [x] 保留标签栏、终端区、SFTP 区及其现有行为。

验收：可在概览和终端工作区之间切换，既有连接不受影响。

## 第二阶段：首页

- [x] 欢迎区和“新建连接 / 打开连接管理器”入口。
- [x] 总连接数和最近使用列表，数据来自已保存会话。
- [x] 按已支持协议计算 SSH、SFTP 统计。
- [x] 补齐命令、连接、文档等快速操作入口。

验收：首页入口可用，统计和最近连接显示真实数据。

## 第三阶段：连接工作区

- [x] 左侧主机摘要和紧凑系统监控。
- [x] 中间标签栏、终端主区域、分屏与标签拖动。
- [x] 下半部分保留 SFTP 文件操作、可调整高度、可最小化。
- [x] 将工作区尺寸、底部快捷操作和文件区视觉层级按 V0.5 布局收紧。

验收：SSH、终端输入、SFTP 传输、分屏、标签拖动和侧栏折叠均正常工作。

## 第四阶段：视觉统一

- [x] 全局/会话侧栏收紧至约 210px，并为窄窗口保留合理最小尺寸。
- [x] 统一按钮层级、边框、留白、字号及 hover/选中/禁用状态。
- [x] 校验浅色主题下终端高对比度，以及中英文文案和图标。

验收：在 1366×768 下首页和连接页不拥挤；缩小窗口时面板仍有可用最小尺寸。

## 实施顺序

1. 完成命令、设置页面路由及导航入口。
2. 统一首页统计口径和快速入口。
3. 收紧连接工作区的侧栏、文件区与快捷操作布局。
4. 执行构建、交互回归和 1366×768 视觉验收。

## 当前边界

- SSH 是目前唯一保存的连接协议；SFTP 统计来自活跃的 SFTP 句柄。
- 命令管理器已作为独立页面和导航入口落地；命令模板的持久化 CRUD 属于后续功能，不在本次布局重构范围内。
