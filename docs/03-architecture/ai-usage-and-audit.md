## 请求与用量

2026-10-13 首轮自动命名增加 `title` 请求用途，与 `chat`、`provider_test` 区分。命名的实际用量计入所属会话和首轮，工具调用关联只选当前轮的 chat 请求；后台命名不能改变后续聊天的请求归属。触发与取消规则见 [AI 契约](ai-conversations.md#首轮后台命名2026-10-13)。

同日增加 `followup` 请求用途，用于已完成回复下方的续聊建议。生成请求关联原用户轮、独立记录请求 ID 与实际用量，在审计中标记“续聊建议生成”；格式无效、超时和取消时保留已收到的用量，失败不改变主回复状态。该请求没有工具能力，不参与工具调用归属。候选作为新消息发送后，新轮请求仍为 `chat`。细节见 [AI 契约](ai-conversations.md)。

用户发送产生稳定用户轮 ID；每次 Provider 请求产生独立请求 ID，保存模型和 Provider 名称快照、HTTP 状态、首字与结束时间、服务响应标识、状态及可选 usage。`src/ai/usage.rs` 和 MCP 审计领域类型定义口径，`provider.rs` 接收 SSE/JSON 元数据，runner 持有独立请求记录，`service/audit.rs` 更新聊天快照及审计。删除聊天后，仍在结束的请求可以结算独立审计。

`stream_options.include_usage` 可关闭，不自动重试生成请求。空 choices 的 usage 尾帧、同一网络块内多个元数据帧、正文校验失败前取得的 usage 均有独立处理。请求 ID 是更新键，不按分片、消息或工具次数累加。缺失和部分用量保留未知；已知输入/输出可求和，缓存和推理是分项。连接测试标记为本地设置测试，不归到聊天；外部 MCP 不创建模型用量记录。旧历史没有用量，不补估算。

聊天内保留会话累计请求数据；独立审计中的明细和全局汇总只覆盖留存范围。会话页面优先展示聊天累计数，下方过滤仅影响审计明细，清理审计不会清除聊天累计数。

2026-10-13 修正进行中请求被提前计为未知的问题，落实批准设计中的“尚未返回”与“结束后缺失”区分。汇总满足 `requests = confirmed + pending + unknown`：完整 usage 为 confirmed；未结束且 usage 不完整为 pending；结束（含失败、取消、中断）仍不完整为 unknown。收到的分项继续保留，真实零值属于已确认；下一轮请求不能消除上一轮的未知记录。同日用户确认紧凑布局后，用量并入输入框顶部，`app/ai/usage.rs` 仅缩写显示数字、附不完整标记，悬停复用完整标签并在 pending/unknown 非零时显示对应计数，点击仍进入原审计。审计汇总复用请求操作的终态优先索引判断等待状态，无新增磁盘字段、迁移或历史重写；启动恢复后等待请求转为中断未知，已有完整用量继续保留。

## 操作与审批链

`Context` 保存来源、对话、用户轮、模型请求、逻辑工具、Engine 任务、客户端和目标关联，生成的关联 ID 不受自定义脱敏表达式影响。结构化文件操作按 create/update 分类；Shell 始终显示命令执行/未分类，分类不参与授权。用途采用已有模型说明并标明来源，不额外调用模型猜测动机。

内置工具申请、缓存复用、未执行、真实执行、结果和取消分别记事件。Engine 任务保存请求、目标及授权摘要、策略版本、审批快照、文件前后正文、命令结果和退出状态。权限/凭据审批与预算决定分别保留，预算决定区分应用和系统通知渠道。自动 SSH 会话清理也记开始与完成。`get_task` 请求保留参数及响应元信息，正文引用任务结果；列表折叠成功轮询，递归时间线可追踪子操作和原始请求。

外部 stdio helper 将有界原始参数传入已认证 IPC，未知工具和参数错误可在 GUI 留存。认证失败不记 proof，不把未验证身份当作已认证客户端；无法解析、超大或超时帧只记录受限拒绝元信息。GUI 不在线的 helper 尝试独立加密记录传输失败，并回报 `audit_persisted`，不代表远端执行。

## 存储与生命周期

`crates/mcp/src/audit/` 使用一个后台线程拥有 SQLite 连接和系统凭据操作。跨线程有界队列为 32 项；查询单页最多 200 条，搜索每批最多扫描 1000 行或 16 MiB 密文。UI 只异步请求，关闭窗口结束刷新循环。

存储位于本机配置目录的 `audit/events.sqlite3`。索引保留匿名哈希 ID、时间、固定枚举和统计数字；参数、主机、标题、用途、正文及前后内容位于 XChaCha20-Poly1305 密文中，以事件 ID 为 AAD。SQLite WAL 中同样只写密文正文。密钥通过系统凭据库保存，数据库只存验证密文；已有绑定失效时拒绝生成新密钥覆盖旧数据。首次初始化用立即事务串行化 GUI/helper 的密钥创建和字段迁移。

内置脱敏覆盖命名秘密、认证头、私钥块、URL 凭据等，可追加最多 32 条正则。已知凭据文件不留正文或修改前后内容。脱敏不能识别所有业务秘密，规则仅作用于新记录，不回写旧密文。单字符串超过 1 MiB、节点超过 4096 或深度超过 32 时保留截断标记；单事件密文前文档上限 3 MiB。实际工具/模型截断和审计截断分别记录。

默认保留 90 天，容量 512 MiB，达到 90% 提示；不为腾空间删除未过期记录。按操作整体清理过期事件；模型明细按留存时间清理。存储失败仅保留脱敏内存环（512 条/16 MiB），没有明文磁盘回退。新命令/写入必须等待执行开始事件落盘；失败时不执行。等待后重新检查取消、客户端和权限，查询及必要会话清理可继续。恢复存储不重试远端操作；内存环和队列可能丢失的记录有缺口说明。

只有已占用 IPC 端点的 GUI 执行旧摘要导入和启动恢复，helper 不恢复活动任务。原 `mcp/audit.jsonl` 保留兼容读写，首次导入仅是旧摘要，不伪造正文、审批或用量。旧实例未结束请求标记中断，命令/写入标记结果未知，不自动重放。

删除聊天、清理独立审计和清理旧摘要是三个独立动作。审计清理/设置/导出记管理事件。CSV 导出当前页摘要及已知用量，防止公式字段被直接解释；正文 JSON 需统一确认弹窗，后台分页读取所选操作完整时间线，上限 64 MiB，超过时拒绝导出。导出文件是脱敏明文，不自动上传、同步或发送。

## 实际限制

静态密文认证能检测正文修改，未实现独立外部见证或完整 HMAC 事件链，不能证明本机记录从未被删除，也不保护同用户/管理员运行中的恶意进程。索引数字不是外部账单依据。

客户端筛选来自当前加载记录，机器来自打开窗口时的保存配置及已加载快照，会话来自聊天及已加载记录；搜索和分页可发现更早记录。详情页每次加载 50 条，最多保留最近加载的 200 条，手动加载更早事件时淘汰较新的页面；刷新重新加载最新事件。JSON 预格式化在后台完成，导出会读取全部相关页。现有 SSH、文件操作及模型适配的实际返回内容决定可记录范围。

2026-10-12 在用户明确授权后执行了 Windows 格式检查、Clippy、全目标测试和 debug/release 构建；实际结果及原生验证范围见[质量记录](../04-quality/ai-usage-and-audit.md)。macOS/Linux 和真实远端服务不在本轮运行验证范围内。

debug 程序提供 `--audit-preview`（可加 `--dark --english --compact`），复用生产 `AuditPanel`、详情、筛选和统一确认框，在独立临时目录注入合成加密数据。此入口不启动用户配置、SSH、模型或应用服务，不属于 release 功能。确认层在面板公共 Render 外层呈现，覆盖列表、详情和设置的所有分支；GPUI 回归使用不启动后台查询的初始状态，存储线程在单元/集成和原生预览中另行验证。
