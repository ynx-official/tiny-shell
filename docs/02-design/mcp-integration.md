# TinyShell MCP 功能设计

> 状态：Draft  
> 最后更新：2026-10-10  
> 关联：[文档索引](../README.md)、[项目规范](../../AGENTS.md)、[统一确认弹窗](confirmation-dialogs.md)

TinyShell 作为 MCP Server，让外部 AI 客户端使用用户已保存并授权的 SSH 连接，执行远程命令、浏览目录和读写文本文件。连接凭据由 TinyShell 内部使用；用户可以在应用内查看 AI 任务、确认受控操作、取消任务或撤销访问。

## 已确认范围与设计假设

已确认的产品要求：

- 第一版面向已保存的 SSH 连接，支持命令执行和远程文件读写。
- 同时提供只读、受控执行、完全访问三种权限模式，由用户选择。
- 参考提供的 MCP / CLI 设置截图，结合现有原生桌面工作流设计。
- 保持 Rust、GPUI、Tokio 技术栈及 awesome-design-md / sentry 风格。

当前代码事实：

- `src/main.rs` 直接启动 GPUI，并声明 Windows GUI 子系统；没有 MCP 或通用 CLI 入口。
- `src/backend/ssh.rs` 已有 SSH 认证、代理、独立 exec channel、系统采集和 Docker 命令执行。
- `src/session/session_types.rs` 的 `Session` 包含连接凭据。MCP 必须使用独立的公开 DTO，禁止直接序列化 `Session`。
- `src/sftp/text_file.rs` 已有文本编码、内容版本比较、临时文件保存、恢复备份和保存后读取校验，但读写接口目前是 SFTP 模块内部接口。
- `src/session/host_key.rs` 首次遇到未知主机密钥时自动记录，已记录密钥变更或被撤销时拒绝连接；现有流程不是首次指纹确认弹窗。
- 设置窗口默认 980 × 700，最小 720 × 520，侧边栏宽 180；MCP 页需要适应现有窗口尺寸。
- 仓库尚未实现 MCP 桥接、客户端注册或 MCP 授权策略。

以下内容是本方案的推荐设计，尚未作为已批准产品规则：本机桥接架构、首次启用行为、连接授权默认值、数据保留期限及第一版范围外事项。本文中的界面数值和资源限额同样属于待验证的设计参数。

## 用户场景与功能边界

目标用户是在外部 AI 客户端中编写代码、排查故障或维护服务器，同时使用 TinyShell 管理 SSH 连接的开发者。

典型流程为：用户在 TinyShell 启用 MCP → 选择权限和连接 → 注册外部客户端并复制配置 → AI 枚举获准连接 → 打开 AI 专用 SSH 会话 → 执行命令或读写文本 → 用户在 TinyShell 查看任务结果。

例如，用户要求 AI“检查测试环境的 Nginx 配置并修正一处端口设置”。AI 读取已授权连接和配置文件，提交带原文件版本的修改，再运行验证命令。受控模式下，用户先看文件差异和完整命令再批准；完全访问模式下直接执行并记录结果。这个例子只说明流程，第一版不提供固定的 Nginx 运维模板。

第一版包含 SSH 专用会话、非交互式命令、目录浏览、文本读取、文本创建和更新、任务查询与取消、应用内授权及操作记录。

第一版范围外建议：

- TinyShell 内置 AI 聊天、模型 API Key、模型计费与 MCP Client 功能。
- 通过公网访问 TinyShell 的 MCP、远程 HTTP 服务及后台常驻服务。
- 操作本地终端、RDP、同步配置、密钥导出、连接新增或删除。
- 往用户正在使用的终端注入按键，读取既有终端历史，交互式 TUI 或密码输入。
- 独立 CLI 产品、二进制上传下载、SSH 隧道管理、结构化删除和批量主机编排。

完全访问中的任意命令可能自行实现删除、传输或隧道等行为。上述范围外事项指第一版不提供对应专用工具和界面，不能表述为 Shell 的安全限制。

## 设置界面与连接流程

### 页面结构

在现有设置侧边栏新增“MCP”。第一版不显示尚未实现的 CLI 页签。页面上方固定显示启用开关、桥接状态与紧急停止入口，下方使用“访问权限 / 客户端接入 / 操作记录”三个页签。

```text
设置 / MCP                              启用 [开关]
本机桥接：运行中 · 2 个客户端 · 1 个任务     [停止所有 AI 任务]

访问权限 | 客户端接入 | 操作记录

权限模式
  ○ 只读        ○ 受控执行        ○ 完全访问
  当前模式的简短说明                [查看能力对照]

连接范围
  ● 指定连接    ○ 全部 SSH 连接
  [搜索名称或分组]
  [✓] 测试环境     SSH      已授权
  [ ] 正式环境     SSH      未授权

所选模式与授权范围立即生效
```

客户端接入页使用紧凑表格，列出客户端名称、检测状态、连接状态和操作；选中一行才展开对应配置。操作包括“复制配置”“检查桥接”和“撤销接入”。检测到客户端可执行文件不等于客户端已配置，配置已复制也不等于连接成功；“已连接”必须来自实际握手。

可以提供 Claude Code、Codex、Cursor、OpenCode 的展示模板及“通用 MCP 客户端”。具体配置格式和注册命令在实现时按各客户端官方资料核对。第一版以复制配置为主，不自动改写客户端配置文件；“在 TinyShell 中启动客户端”作为后续可选能力。

操作记录页显示时间、客户端标签、连接名称、操作类型、状态与耗时。当前运行任务可展开查看命令、输出或文件差异；历史记录按下文的隐私规则保存。

### 首次启用与授权

推荐初始关闭 MCP。首次启用时必须完成模式和连接范围选择；只读作为界面推荐项，默认没有授权连接。用户选择完全访问时，在启用前确认一次权限含义，之后不再逐次弹出 TinyShell 操作确认。

连接范围有两种：

- 指定连接：按稳定连接 ID 勾选，后续新增或导入的连接不自动授权。
- 全部 SSH 连接：包含当前和以后新增的 SSH 连接；旁边持续显示“新增 SSH 连接也会开放”，选用时明确确认这个后果。

RDP、已删除连接与临时连接始终不在范围内。重命名或移动分组保持授权；修改主机、端口、用户、认证引用或代理目标时，连接进入“需要重新授权”，即使使用“全部 SSH 连接”也不能静默把旧授权迁移到新目标。

第一版使用全局权限模式和全局连接范围，所有已注册客户端共享这组上限。每个客户端仍有独立接入开关和可撤销注册。按客户端或连接设置不同权限等级可后续增加。

授权策略保存在本机专用存储中，不进入 WebDAV / S3 同步或连接归档；在新设备上需要重新启用和授权。

### 原生视觉与交互

延续项目已批准的原生桌面适配：8px 间距节奏、平面分组、现有主题颜色、系统 UI 字体和等宽配置片段。区块内边距建议 16px，区块间距 24px；状态使用文字和图标，不只靠颜色。

980px 窗口下三种模式横向排列；720px 窗口或放大字体后转为纵向。连接列表独立滚动，命令片段支持水平滚动和一键复制；长连接名称保留可查看全文的入口。增加正常、悬停、焦点、禁用、加载、空列表、桥接断开和错误状态。

简单授权与危险操作提示复用 `ConfirmationDialog`。文件差异、命令详情和批量目标列表使用专门审阅面板，确认按钮沿用既有组件约定。所有界面文本同步维护 `locales/zh-CN.yml` 与 `locales/en.yml`。

## 三种权限模式

| 能力 | 只读 | 受控执行 | 完全访问 |
| --- | --- | --- | --- |
| 列出授权连接、查看 MCP 状态 | 允许 | 允许 | 允许 |
| 打开或关闭自己的 AI SSH 会话 | 允许 | 允许 | 允许 |
| 浏览目录、读取远程文本 | 允许 | 允许 | 允许 |
| 执行任意非交互式命令 | 禁止 | 每次确认 | 直接执行 |
| 创建或更新文本文件 | 禁止 | 查看目标和差异后确认 | 直接执行 |
| sudo、删除、重启等非交互式命令 | 禁止 | 展示命令并确认 | 直接执行 |
| 查询、取消自己的任务 | 允许 | 允许 | 允许 |
| 自动提供登录密码、sudo 密码或私钥内容 | 不提供 | 不提供 | 不提供 |
| 绕过连接授权、主机密钥校验、文件冲突或系统权限 | 不允许 | 不允许 | 不允许 |

只读模式不接受用户或 AI 提交的 Shell 字符串，包括看似只读的 `cat`、`grep` 等；读取使用固定的 SFTP 接口。会话初始化不自动启动现有系统监控探测和 Docker 查询。

受控执行不依赖“安全命令白名单”或危险关键词来免除确认。Shell 的脚本、重定向、替换和解释器使关键词过滤不足以保证只读。确认面板展示完整命令、工作目录、连接目标和客户端标签；批准仅适用于该任务不可变的参数和连接版本。

完全访问取消 TinyShell 的逐操作确认，但仍执行协议、授权、参数和资源限额检查。任意命令拥有远程 SSH 账号原有权限，可能读取敏感文件、联网或修改系统；目录限制无法把任意 Shell 变成沙箱。需要严格隔离时，应使用远程受限账号和操作系统隔离。

第一版不申请 PTY、不接受命令 stdin，也不弹窗收集提权密码；需要交互式认证的命令返回失败或超时。`sudo -n` 能否执行由远程 sudo 策略决定。

读取文件和命令输出会把内容提供给用户所选的外部 AI 客户端；外部客户端可能将其发送给模型服务。设置文案应明确这个数据流，不能承诺“数据永不离开本机”。桥接不提供连接凭据导出，但任意命令和文件读取仍可能接触远程账号可访问的敏感内容。

## 桥接架构与模块边界

### 方案比较

| 方案 | 收益 | 成本与约束 |
| --- | --- | --- |
| 独立 MCP 桥接程序连接运行中的 TinyShell，推荐 | 凭据、权限、任务及 SSH 会话由应用统一管理；适合可见确认与撤销 | 需分发桥接程序并实现本机 IPC |
| 主应用增加 `mcp` 启动模式 | 配置入口看起来更简单 | GUI 和 stdio 生命周期耦合，Windows GUI 子系统及日志初始化需单独验证 |
| 独立无界面 MCP 服务直接打开连接存储 | 应用关闭后仍可使用 | 需复制凭据处理、连接生命周期和授权交互，超出首版范围 |

推荐路径：外部 MCP 客户端通过标准 stdio 启动 `tiny-shell-mcp`，桥接程序通过本机 IPC 调用 TinyShell 中的应用协调器，再由协调器调用 SSH / SFTP 服务。stdio 是 MCP 标准传输之一，stdout 只输出 MCP 消息，日志输出到 stderr。[MCP 传输规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)

```text
外部 AI 客户端
      │ MCP / stdio
tiny-shell-mcp
      │ 已认证的本机 IPC
TinyShell 应用协调器
      ├── 本机授权策略与任务状态
      ├── GPUI 审阅与确认
      └── SSH 执行服务 / SFTP 文本服务
                      │ SSH
                   远程主机
```

桥接只取得获准连接的公开信息和操作结果，不直接加载整个连接配置、不持有 SSH 凭据。请求鉴权、权限决策和实际执行必须在应用端完成，不能由桥接传来的 `approved` 标记或客户端名称决定。

### 模块职责

| 建议位置 | 职责 |
| --- | --- |
| `src/bin/tiny-shell-mcp.rs` | stdio 程序入口，加载本机注册，连接应用，处理退出 |
| `src/mcp/` | MCP 协议映射、共享 IPC 消息、公开 DTO、策略和任务模型 |
| `src/app/mcp/` | 应用级协调器、审阅队列、授权变更与原生任务视图 |
| `src/app/settings/mcp.rs` | 设置页，接入现有 `settings/view.rs` |
| `src/backend/` | 抽出并复用连接认证与非交互式 exec 服务 |
| `src/sftp/` | 暴露面向服务的目录和文本操作，保留编码与保存规则 |
| `src/session/` | 提供受控的连接查找和凭据解析；不暴露给 MCP 序列化 |

应用协调器是进程级状态，多个 GPUI 窗口共享一份授权和任务仓库。多应用进程使用同一配置目录时，只允许一个进程拥有桥接端点；冲突进程明确显示状态，桥接不自动连接任意一个进程。

AI 使用独立 SSH 会话，与人工终端分开；同一客户端的任务可复用自己的 AI 会话。不同客户端的会话与任务 ID 相互隔离，不能关闭对方会话、读对方结果或接管人工标签页。第一版结束后按空闲时间释放连接，不增加第二套连接配置。

### 本机 IPC 与接入注册

Windows 使用禁止远程访问的命名管道，并设置当前用户 ACL；macOS / Linux 使用当前用户私有目录中的 Unix domain socket。第一版不监听 TCP 端口。

用户在设置中注册客户端时，应用生成注册 ID 和随机接入秘密；秘密仅保存于当前用户可读取的本机文件。复制的客户端配置包含桥接路径和非秘密注册 ID，不包含密码、Token 或私钥。IPC 请求必须完成秘密认证，单凭客户端自报的 `clientInfo.name` 不能获得访问权限。

客户端标签用于展示，不能证明调用方真的是某个品牌客户端；同一操作系统用户下能读注册秘密的程序属于本机信任边界，第一版不宣称能隔离恶意同用户进程。

应用运行实例具有随机 generation，桥接请求绑定实例和客户端注册。重启后旧会话、任务票据与审批失效；桥接重新发现和认证新实例。应用没有运行时返回 `APP_NOT_RUNNING` 并提示用户启动，不能自动创建无人可见的服务。

Windows 安装版与便携版、macOS app bundle、Linux tar.gz 与 AppImage 均需分发可稳定调用的桥接入口。AppImage 配置不能引用临时挂载目录；可通过外层 AppImage 的明确桥接参数转发到内部 helper，具体入口需要打包验证。

### SDK 与 Rust 版本

优先评估官方 Rust SDK `rmcp`，只启用 server、stdio 所需功能；不手写完整 MCP 协议。当前 SDK 主分支声明 Rust 1.88，而项目声明 1.85，两者不能直接视为兼容。[官方 SDK 清单](https://raw.githubusercontent.com/modelcontextprotocol/rust-sdk/main/Cargo.toml)

实施前需要选定并验证兼容项目最低 Rust 版本的 SDK 发布版本及传递依赖。若没有合适版本，单独提交提高最低 Rust 版本的架构决策供用户确认；不在实现过程中静默提高版本。协议版本在初始化时协商，以所选 SDK 和实际客户端共同支持的版本为准。

## MCP 工具契约

第一版建议提供十个工具。会话和任务 ID 是应用签发的临时引用，客户端只能使用自己的引用，不能传入任意主机或凭据。

| 工具 | 主要参数 | 可观察结果 |
| --- | --- | --- |
| `get_status` | 无 | 应用和桥接版本、当前模式、连接与任务限额 |
| `list_connections` | 搜索词、分页游标 | 获准 SSH 连接的 ID、名称、分组、主机、端口、用户名和状态 |
| `open_session` | `connection_id`、`request_id` | `task_id`，完成后取得 `session_id` |
| `close_session` | `session_id`、`request_id` | 关闭自己的会话与相关任务后的状态 |
| `run_command` | `session_id`、`command`、可选 `cwd`、`timeout_ms`、`request_id` | `task_id`，任务中含 stdout、stderr、退出码及截断标记 |
| `get_task` | `task_id`、输出游标、读取限额 | 任务状态、分页输出或文件写入结果 |
| `cancel_task` | `task_id` | 取消请求是否被接收及当前执行状态 |
| `list_directory` | `session_id`、绝对路径、分页游标 | 目录项、类型、大小、时间及下一页游标 |
| `read_file` | `session_id`、绝对路径 | 文本、编码、换行格式、内容版本与大小 |
| `write_file` | `session_id`、绝对路径、内容、`create/update`、预期版本、`request_id` | `task_id`，任务中含保存后的内容版本或冲突 |

工具使用 JSON Schema 描述输入和输出，返回 `structuredContent`，并保留兼容性的文本表示。权限拒绝、冲突等操作错误使用 `isError: true`；传输或请求结构错误使用 JSON-RPC 错误。这符合 MCP 对工具结果与错误的区分。[MCP 工具规范](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)

应用任务使用普通工具提交及查询，以兼容不同客户端；第一版不依赖客户端支持实验性的 MCP Tasks、elicitation 或实时通知。进度通知可作为可用时的补充，任务查询始终可用。

`list_connections` 通过显式白名单组装 DTO，不包含密码、代理密码、私钥路径、私钥内容或口令。名称和主机信息也只对已授权连接返回。终端输出与远程文件均视为外部数据，不能将其中的文字作为扩大 TinyShell 权限的依据。

### 命令与任务行为

每次命令使用独立、无 PTY 的 exec channel，不保证沿用人工终端或上一次命令的目录、变量和 Shell 状态。省略 `cwd` 时使用远程账号的默认登录目录；指定目录时必须传绝对路径。远程 Shell 类型需要识别并使用对应转义方式，不能把 Linux POSIX 拼接逻辑直接用于 Windows SSH；无法识别时返回 `UNSUPPORTED_SHELL`，不猜测拼接方式。

建议默认执行超时 30 秒、最大 300 秒；每个客户端最多两个执行任务、每个连接最多一个变更任务。单任务输出缓冲上限 1 MiB，查询每次最多 64 KiB。到达输出上限后继续排空通道或终止任务，不能阻塞 SSH 接收；结果明确标记截断。所有限额在后端检查。

任务状态包括 `queued`、`awaiting_user`、`running`、`succeeded`、`failed`、`cancel_requested`、`cancelled`、`timed_out`、`interrupted` 和 `outcome_unknown`。等待确认建议最长两分钟，并与执行超时分别计时；拒绝和过期转为 `failed`，分别附带 `APPROVAL_DENIED` 和 `APPROVAL_EXPIRED`，操作不执行；应用关闭则转为 `interrupted`。

同一客户端的同一个 `request_id` 和相同参数映射到同一任务，重复提交返回已有任务；同 ID 不同参数拒绝。去重记录在当前应用实例内至少覆盖任务保留期；应用重启后不自动重放变更请求。

网络中断、保存后校验失败或命令退出状态丢失可能造成“操作已经发生，但结果未确认”。返回 `outcome_unknown`，要求先检查远程状态，不能将它当成普通失败自动重试。

取消、禁用 MCP、撤销客户端或撤销连接时，先阻止新任务和待批准任务，再尽力结束相关 exec channel 与 AI 会话。关闭 SSH channel 不保证终止远程后台进程；任务记录必须如实显示无法确认的取消结果。

### 文件行为

第一版文本文件上限建议 256 KiB；不把现有编辑器的 5 MiB 上限直接等同于 AI 输出预算。读取返回内容版本以及编码和换行格式；AI 更新已有文件必须带回完整文件对应的预期版本，不能根据截断内容覆盖。

更新沿用已有 SFTP 保存服务的内容比较、临时文件、恢复备份和保存后读取校验。原文件版本不匹配时，即使完全访问也返回 `FILE_CONFLICT`；工具不提供 `force` 参数。创建采用排他创建或等效的不覆盖策略，目标已存在时返回冲突。

更新应保留原编码、换行和权限；新建文本默认 UTF-8 无 BOM、LF 换行，权限采用远程账号的默认 umask。不支持的编码、符号链接写入、目录、二进制或超过限额的文件返回明确错误。读目录的符号链接可以作为条目展示；首版写工具拒绝符号链接目标，避免审阅对象和实际写入对象不一致。

现有保存实现可缩小竞态窗口，但 SFTP 的读取与重命名不能保证对其他进程的全局原子版本比较；不承诺不存在任何并发覆盖。应用内写同一路径需要串行。服务器不支持原子覆盖时，恢复备份流程同样不能宣传为全程原子保存；替换阶段即使收到取消，也先完成恢复或校验，再报告状态。

建议首版要求绝对远程路径；文件服务在操作前解析并验证路径类型。任意命令的账号权限边界与文件工具的输入校验分别生效，不能宣称文件工具的路径规则约束了 Shell。

### 错误与隐私

对外提供稳定错误码，例如 `MCP_DISABLED`、`APP_NOT_RUNNING`、`CLIENT_REVOKED`、`CONNECTION_NOT_ALLOWED`、`PERMISSION_DENIED`、`AUTH_REQUIRED`、`HOST_KEY_CHANGED`、`FILE_CONFLICT`、`OUTPUT_LIMIT`、`TIMEOUT` 和 `OUTCOME_UNKNOWN`。完整原始错误不得直接拼入结果，避免泄露凭据、私钥路径或本机配置。

需要登录密码或私钥口令时，任务进入 `awaiting_user`，用户通过 TinyShell 原有认证表单完成；MCP 工具不接收认证秘密。主机密钥检查沿用当前流程：未知密钥自动记录，变更或撤销时失败；MCP 不能自动删除或覆盖已记录密钥。

历史记录建议只保存时间、注册 ID、连接 ID、操作类型、权限模式、耗时、结果和退出码，不保存原始命令参数、文件正文、差异或输出。建议最多保留七天或 10 MiB，可在应用中手动清空；全部在本机，不参与同步。

活动任务的详细内容仅在内存保存，完成后建议保留 30 分钟，供查询结果；届时返回结果已过期，不能静默重新执行。审阅期间的内容可能敏感，界面默认折叠。输出脱敏可以作为补充，不能保证识别命令和文件中全部秘密。

## 验收与分阶段交付

| 场景 | 验收结果 |
| --- | --- |
| 未启用或撤销注册 | 任意工具均无法执行连接操作；公开状态不泄露连接列表 |
| 枚举与直接猜测未授权连接 ID | 列表不出现目标，直接访问仍被应用端拒绝 |
| 只读模式提交命令或文件变更 | 拒绝请求，SSH exec 或 SFTP 写接口没有被调用 |
| 受控模式提交操作 | 取得待确认任务；拒绝或过期不执行；批准后最多执行一次 |
| 完全访问提交命令 | 在授权范围内直接执行，记录任务，仍检查协议与资源限额 |
| 审阅后连接目标或权限变化 | 旧批准失效，执行前重新验证，不向变化后的目标发送操作 |
| 修改文件前另一客户端或用户编辑文件 | 检测到版本冲突时拒绝覆盖并返回当前版本 |
| 重复请求或断线重连 | 同实例相同请求不重复执行，状态不明时不自动重试 |
| AI 执行时人工终端输入 | 使用独立通道，人工标签页和输入不被接管 |
| 客户端 A 读取或取消客户端 B 的任务 | 拒绝，不泄露任务正文或输出 |
| 应用重启、关闭、取消或超时 | 生命周期可观察，遗留远程进程的结果不伪装为已取消 |
| Windows、macOS、Linux 打包 | helper 可被客户端启动，stdout 无日志，路径更新后仍有效 |
| 界面尺寸、主题和语言变化 | 720 × 520 与 980 × 700 下可完成授权，长文本不遮挡操作 |

## 实施前需要确认的决策

产品范围已确认到 SSH 命令与远程文件读写，三种模式均需提供。以下决策在实现前统一评审：

- 是否采用独立 helper、本机 IPC、应用必须运行的架构。
- 是否采用初始关闭、首次推荐只读、显式授权连接和“全部连接包含新增连接”的规则。
- 是否接受受控模式对每条任意命令和每次文件写入确认，以及完全访问的远程账号权限含义。
- 是否将首版限定为非交互式命令和小型文本，延后专用上传下载、删除、隧道和 CLI。
- 是否接受上述外部 AI 数据流说明、记录范围和保留期限。
- SDK 兼容性验证后，是否需要调整项目最低 Rust 版本。
