## 1. 已确认及合理假设

已确认：

- 统计每个本地会话的 Token 用量。
- 详细记录内置 AI 每次操作的增删改查类型、用途、请求、审批和结果，方便审计。
- 外部 MCP 不计入 Token；记录外部实际传入的操作和参数。
- 用户已选择：默认详细留存参数、命令与结果正文，脱敏后在本机加密保存。API Key、密码、私钥等仍需脱敏。
- 原规划轮次只做设计；2026-10-12 用户随后确认实施。本地编译、测试、构建和运行仍须单独明确要求。

合理假设：

- “本地会话”按 AI 历史中的一段对话理解；以稳定 conversation_id 归属，关闭侧栏、重命名或重启不产生新会话。
- 首版统计 Token 数量；金额、服务商账单核对和模型定价管理暂不纳入。
- 审计范围为内置 AI 与 MCP / CLI 经过 TinyShell 的操作。人工终端键入内容、外部客户端聊天和思考内容不在可观察范围内。

2026-10-12 用户确认按本设计实施，采用下列推荐规则：

1. 审计保留周期及容量：建议默认 90 天、可配置；容量接近限制先提示，不静默删掉未过期记录。
2. 删除 AI 对话是否同时删除审计：建议聊天删除与审计清理分别进行；保留审计的影响必须在删除确认中说明。
3. 采用本机 SQLite 索引与认证加密正文，见第 8 节方案比较；不引入服务器数据库。
4. 导出范围：建议首版手动导出脱敏摘要 JSON/CSV，正文导出单独确认；不自动同步或上传。
5. 审计不可持久化时的执行策略：阻止新的变更操作，查询可在明确的临时记录状态下继续；该规则包含在用户批准的设计中。

## 2. 规划时的实现基线与缺口

| 当前实现 | 证据与缺口 |
| --- | --- |
| AI 本机历史已有认证加密 | `src/ai/storage.rs` 使用 XChaCha20-Poly1305；可复用加密方法和系统凭据机制，但不把审计生命期绑定到聊天文件。 |
| Provider 只返回 Message | `src/ai/provider.rs` 的 JSON/SSE 解析没有保存 usage；请求没有 include_usage。旧历史不能恢复精确用量。 |
| 每个用户轮可能有多次模型请求 | `src/ai/service/runner.rs` 模型 → 工具 → 模型循环；预算继续沿用同一用户轮。不能用消息条数代替模型请求数。 |
| AI Activity 可关联调用和任务 | 已有 message_index、tool_call_id、task_id；仍缺稳定 turn_id、模型请求 ID、审批事件、审计事件序号。 |
| Engine 有终态元数据审计 | `crates/mcp/src/engine.rs::audit` 只写时间、来源 ID、目标 ID、操作、模式、状态、退出码；没有参数、用途和审批时间线。 |
| MCP 审计默认 7 天 / 10 MiB | `crates/mcp/src/storage.rs`；当前界面只读取最近 20 条，无法承担完整审计查询。 |
| 参数错误可能停留在 helper | `crates/mcp/src/server.rs::call_tool` 在 IPC 之前解析；非法参数直接返回，不进入 Engine 审计。 |
| 审批拒绝等路径没有独立事件 | approve 分支修改任务状态；不能只靠成功执行后的 audit 恢复审批全过程。 |

这些判断来自源码阅读，未以本轮运行证据宣称验证通过。

## 3. Token 统计口径

### 3.1 统计层级

对话 → 用户轮次 → 模型请求。一次用户发送建立一个 turn_id；工具循环和追加预算仍属于该轮，每次真正发往 Provider 的 HTTP 请求建立独立 model_request_id。

| 指标 | 口径 |
| --- | --- |
| 输入 Token | 服务商报告的输入量；包含本次实际发送的系统提示、历史上下文、工具描述和回送结果。 |
| 输出 Token | 服务商报告的输出量。 |
| 总 Token | 保留服务商 total；缺省且输入/输出完整时可求和并标记“由分项计算”。 |
| 缓存命中 / 缓存写入 | 服务商提供时保留为明细；按该 Provider 的语义解释，不再机械加到总量。 |
| 推理 Token | 服务商提供时展示为输出明细，不与输出重复累加。 |
| 模型请求数 | 实际发出请求的数量；失败、取消也有请求记录。暂停待选择本身不增加。 |
| 数据完整性 | 已确认用量、尚未返回、服务未提供、取消/断流未取得完整用量、旧数据未知。 |

每个请求保存 Provider ID/名称快照、请求模型、服务返回模型、开始/首字/结束时间、状态、HTTP 状态及非敏感请求标识。更换模型、Provider 改名或删除后，历史仍展示当时信息。

### 3.2 汇总规则

- 每个 model_request_id 只结算一次；收到多个相同 usage 更新时不重复累加。
- 对话总量为所属请求的已确认用量之和，同时展示未知请求数，例如“已确认 12,430 · 2 次用量未知”。存在缺失时不把已知部分伪装为完整总量。
- 工具执行本身不增加模型 Token；工具结果被再次发送给模型时，体现在那次请求的输入量中。
- 内置 AI 调用共享 Engine 时，Token 只由 Provider 请求记录入账；不能在 MCP/Engine 层再次入账。
- 外部 MCP 的 Token 字段显示“不计入”；不填 0，也不推断外部模型的消耗。
- Provider 的连接测试独立标为“设置测试”，不归到某段聊天；模型列表刷新不作为生成 Token 请求。
- 历史缺少 usage 标为“旧数据未知”。首版不以字符数估算真实 Token，也不为补统计额外请求模型。
- 正在输出时展示“待服务返回用量”；不按 SSE 分片数递增 Token。
- 已取得 usage 后，即使正文解析失败或用户随后取消，也保留该用量。未取得时为未知，而不是零费用。

### 3.3 流式兼容

支持 Chat Completions 的 Provider 可配置请求 `stream_options.include_usage=true`；JSON 回退也解析 usage。服务不支持这一字段时显示能力说明，并允许用户关闭；不得自动重试可能已被处理的生成请求。

SSE 的 usage 尾帧可没有 choices，解析不能要求其中有正文；finish_reason 不代表已经收到了最终 usage。OpenAI 官方说明取消或断流可能使最终 usage 缺失，因此未知状态必须进入汇总。[官方流式事件文档](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events)

## 4. 审计中的操作类型和用途

### 4.1 类型

| 类型 | 示例与规则 |
| --- | --- |
| 增 | 结构化 write_file(create)；新增对象的申请与结果分别记。 |
| 删 | 外部/内置实际请求的删除操作；当前没有专门删除工具，不为审计新增此工具。 |
| 改 | write_file(update)，记录目标、版本及脱敏前后差异。 |
| 查 | read_file、list_directory、连接/任务/状态查询。 |
| 会话 / 控制 | 建立或关闭 SSH 会话、取消任务、预算继续/终止。 |
| 模型 / 回复 | 模型请求、生成普通答复或总结；用量关联模型请求，不强行归为远端增删改查。 |
| 复合 / 未分类 | 任意 Shell、脚本、管道、多个不同操作，不能保证仅增删改查。 |

结构化工具按契约分类。Shell 分类可作为带来源和置信度的说明，不能作为授权依据；无法确定时保留“命令执行 / 未分类”，不以关键词判定安全。

分别记录 requested_type（请求意图）和执行状态/效果。被拒绝的删除请求不能显示成“已删除”；退出码成功也不能证明所有远端副作用。

### 4.2 用途

- 用户目标：关联本轮的原始请求或受限摘要。
- 具体操作说明：例如“读取 nginx 服务状态，确认是否正在运行”。优先使用确定性的工具/参数模板，无需新增模型调用。
- 模型/客户端提供的说明：可保存原有助手说明或明确提交的用途，标注“模型说明”或“客户端自述”，与执行事实分开。
- 外部 MCP 没有说明时，展示基于工具和参数的操作摘要及“客户端未提供用途”；不补写客户端没有表达的真实动机。
- 目的不完整仍保存已实际执行的工具、参数和结果，不能由事后 AI 文案覆盖执行记录。

## 5. 一次操作保存哪些信息

| 分组 | 建议字段 |
| --- | --- |
| 关联 | event_id、事件序号、operation_id、父操作 ID、conversation_id、turn_id、model_request_id、tool_call_id、task_id、request_id、approval_id。 |
| 来源 | 内置 AI / 外部 MCP·CLI / 本机用户 / 系统；来源注册 ID、当时显示名、应用实例；未认证的自述 ID 明确标记未验证。 |
| 目标 | 保存连接 ID、当时名称与目标快照、SSH 会话 ID、目标身份摘要；无需连接的查询可无目标。 |
| 意图 | 类型、用途、用途来源、工具名、请求原始参数的脱敏版本、规范化后的参数；保留两者差异。 |
| 命令 | 脱敏后完整 command、提交的 cwd、有效目录是否可知、超时设置；Shell 不支持 cwd 时记录拒绝原因，不伪造目录。 |
| 文件 | 路径、create/update、期望/旧/新版本、脱敏前后内容及 diff、编码/大小等实际可取得信息；读取内容是否保留按已确认脱敏规则。 |
| 权限 | 内置/外部模式、策略 revision 或能力代数、目标授权快照、校验结果、拒绝原因。 |
| 审批 | 审批类型、请求与决定时间、有效审阅快照的指纹、决定人/渠道、通过/拒绝/过期/失效、原因、等待耗时。 |
| 执行 | 是否真正开始执行、开始/结束时间、排队/审批/执行耗时、缓存命中或幂等复用、原执行记录 ID。 |
| 结果 | 成功/失败/取消/超时/中断/结果不确定/未执行；脱敏 stdout、stderr、退出码、结构化结果、错误代码及截断标志。 |
| 完整性 | 字节数、截断/脱敏原因、可重建事件序列、schema_version、缺失信息说明、记录落盘状态。 |

命令/结果“完整”指 TinyShell 实际收到且未被现有限制丢弃的部分，不宣称拥有远端全部输出。审计采集应在回送模型的结果压缩之前；分别标记远端捕获上限、审计留存上限和 model_result_truncated。

明确不得保存：Provider Authorization/API Key、MCP 注册秘密、认证 proof、SSH 密码/私钥/口令、预算继续 token。认证交互只记发生时间与是否完成，不记输入值。

## 6. 审批与生命周期时间线

每个操作形成追加的事件序列，而不是反复覆盖最后一个状态：

用户轮开始/结束、模型请求开始/结束和 usage 结算也进入时间线。普通聊天有请求与答复记录；没有工具调用时，远端操作次数为零。助手答复正文按已确认的脱敏加密方式保存或引用加密正文对象，避免重复复制长文本。

```text
请求收到 → 参数校验 → 权限校验 → 审批申请（如需）
                               ├─ 批准 → 再次校验 → 执行开始 → 执行结果
                               └─ 拒绝 / 过期 / 撤销失效 → 未执行
```

- 权限通过直接执行也记录“按完全访问策略执行 / 不需人工审批”，不能显示成人工批准。
- 人工审批绑定完整请求、目标、策略版本和审阅快照；双击或跨窗口重复决定只生效一次，重复尝试可留事件说明。
- 凭据输入和 SSH 信任确认记录为各自交互类型；不得与命令变更批准混淆。
- 预算继续/终止、系统通知按钮的选择单独记作“执行预算决定”。批准追加预算不代表批准 SSH 写入。
- 参数错误、未授权、客户端撤销、任务查询、取消、缓存复用和幂等复用都可追踪。缓存/幂等记录引用原操作，实际远端执行次数保持不变。
- 重启对未闭合记录追加“应用中断 / 结果待核实”；不改写过去事件，不凭记录自动重放操作。
- 成功、失败、拒绝、尚未执行、执行结果不确定分别统计。

外部 get_task 等高频请求保留每次请求的参数和响应元信息；正文只保存新增片段或引用已保存结果。界面默认按原任务折叠，展开可逐次查看，避免轮询刷满列表或重复复制大段输出。

## 7. 外部 MCP 的接收边界

记录范围是 TinyShell/helper 实际收到的请求，不包含外部客户端内部聊天、思考、模型名称或 Token，除非客户端明确传入并标注为自述。

- 在 MCP 入口生成接收请求 ID，记录工具名与脱敏参数，再进行契约校验；非法参数、未知工具也进入拒绝记录。
- GUI 在线时，由已认证的 IPC 接收端统一保存并验证原始请求，避免 helper 的提前解析导致审计遗漏；入口日志和 Engine 事件用同一 operation_id 关联，不显示为两次执行。
- 认证失败只记录有限元数据及原因，不保存 proof，也不把未认证客户端名当作真实身份；畸形/超大帧记长度、指纹和拒绝原因，不无界保存攻击载荷。
- GUI 不在线、IPC 失败等 helper 本地失败需要有界、加密的本地记录路径；上线后按事件 ID 去重合并。秘密服务不可用时明确临时/记录缺失状态，不落明文。
- 外部用途字段作为可选扩展时保持兼容旧客户端；不能直接改变现有 deny_unknown_fields 参数契约。首版可先使用工具/参数摘要。

## 8. 存储方案与模块边界

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| **本机 SQLite 索引 + 加密事件/正文（建议）** | 事务、分页、多进程写入、按会话/来源/时间统计更直接；适合长期详细审计。 | 新增嵌入式存储依赖和版本迁移；需明确索引中可见的元数据范围。 |
| 复用 JSONL，改为分段加密文件 | 复用现有方式，新依赖少。 | 分页、聚合、并发写入、跨 helper 同步、索引恢复和空间回收都需自行维护。 |

用户已确认推荐方案，不引入服务器、MySQL 或网络服务。加密复用既有算法/系统凭据方式，使用独立用途的审计密钥，不直接复制现有聊天密文容器格式。

若采用 SQLite：明文索引仅保留必要匿名 ID、时间、来源/状态枚举和统计数字；主机、用户名、标题、命令、路径、参数、用途和结果位于认证加密 payload。查看一页时解密一页；正文搜索在后台受限解密扫描，支持取消，不建立含敏感正文的明文全文索引。加密 payload 必须覆盖 WAL、临时文件和备份中的正文保护。

建议分工：

- `src/ai/provider.rs`：采集并规范化供应商 usage，单独回传用量与生成状态。
- `src/ai/service/`：产生稳定用户轮/模型请求/逻辑调用关联，记录暂停选择、缓存复用及模型请求结算。
- `crates/mcp` 的独立审计模块：通用事件、加密落盘、查询接口、执行与审批事件；不依赖 AI UI 类型。
- MCP helper/IPC：收取外部原始请求、认证结果和接收失败记录，向同一审计机制交接。
- Engine：唯一的实际执行/审批事实来源；审计事件不改变权限和幂等边界。
- `src/app/`：统计页、筛选、详情、导出与清理确认，沿用 Sentry 紧凑原生风格。

不依赖聊天界面是否展开来采集数据；不把 UI 文本或旧日志反解析为权威审计。

## 9. 页面和用户流程

| 页面/入口 | 内容与交互 |
| --- | --- |
| AI 历史列表 | 每段对话显示累计已确认 Token、完整性状态；提供统计/审计入口。 |
| 对话底部用量 | 轻量显示“本轮 / 本会话：输入、输出、总量”；展开看请求明细；不影响现有处理动画和 SSE 跟随。 |
| 会话统计页 | 对话标题、Provider/模型分布、累计与分轮输入/输出、缓存/推理明细、未知请求数、请求耗时；可进入某一用户轮。 |
| 统一审计列表 | 内置 AI / 外部 MCP 筛选；按时间、连接、对话、客户端、类型、状态、审批结果搜索。默认每行显示时间、来源、类型、用途、目标、审批、结果与耗时。 |
| 操作详情 | 概览、原始/有效参数、命令或文件差异、结果、审批与完整时间线；缓存命中和幂等复用可以跳到原操作。 |
| 审批记录视图 | 权限审批与预算决定分组；显示待审阅/通过/拒绝/超时/失效、渠道和快照；待审批操作可跳到原审阅入口。 |
| 审计与统计设置 | 留存范围、周期、容量、脱敏规则、手动导出和清理；显示存储不可用、临时记录及未迁移旧数据。 |

AI 设置已有“模型服务 / 执行预算 / 通知提醒”分组，建议增加“统计与审计”导航入口；统一审计页从 MCP / CLI 的现有历史入口也能进入，并预选外部来源。权限页保留原来源 Tab，统计不新增或替代任何授权开关。

用量与执行次数并排但分别统计，例如“模型请求 3 次 · 工具申请 4 次 · 实际执行 2 次 · 缓存复用 1 次 · 未执行 1 次”。外部 MCP 仅展示后一组操作指标。

## 10. 留存、隐私与兼容性

- 参数/命令/输出先在采集端脱敏，再进入持久化、索引、导出和应用日志；业务结果仍以当前有效工具协议处理，不因为审计脱敏修改远端执行。
- 优先排除显式秘密字段、认证头、已知凭据值与私钥块；敏感文件正文可只记访问行为和遮盖说明。不能保证通过通用规则识别一切任意业务秘密，界面需允许用户增补规则。
- 正文在本机加密，不参加连接同步；密钥不可用不创建替代密钥覆盖旧密文，也不退回明文存储。
- 分页、大小上限、轮转与容量提示必须避免过长结果拖慢 UI。审计持久化在开始远端副作用前确认，后续失败明确“记录不完整”；不以记录错误为理由自动重试远端操作。
- 保留期、容量行为、对话删除与审计清理分别确认后实施。清理/导出本身可记管理事件；主动删除记录以后，不能承诺保留完整审计链。
- 可采用连续序号与 hash/HMAC 链检测缺页/修改；若同时删除密钥或全部本机记录，无法提供外部可信的不可抵赖证明。首版不宣称“绝对防篡改”。
- 旧 metadata 日志兼容读取为“旧版摘要”；没有的参数、正文、审批或 Token 都标为未知，不伪造补齐。
- 采用新 schema_version 和显式迁移；旧文件保留直至迁移确认完成，降级兼容另行说明。

## 11. 分阶段实施建议

1. 确认统计口径、保留/删除/导出规则和存储方案；同步正式需求、威胁模型与验收。
2. 打通请求 usage → 请求记录 → 用户轮 → 对话汇总；覆盖 SSE 尾帧、JSON、取消、未知值和去重。
3. 建立审计存储及事件关联，接入 AI/外部请求入口、Engine 执行和逐次审批、预算选择。
4. 完成会话统计、统一审计、操作详情、审批记录和设置入口；不把完整详情堆进聊天消息。
5. 用户先手动验收；仅在用户明确要求后运行可能触发编译的测试、Clippy、构建或应用预览。

## 12. 拟验收场景

以下是计划中的测试与手动检查，本轮尚未执行：

- 一轮经历三次模型请求，分项和对话汇总只相加三次；相同 usage 尾帧重复到达不重复计数。
- 最终 usage 的 choices 为空、JSON 回退、尾帧缺失、首字前失败、取消后已知用量分别正确展示。
- 服务商不提供 usage 和旧对话均显示未知；MCP 不计 Token；设置连接测试不计入聊天。
- 文件创建/更新分别分类；复杂 Shell 显示复合/未分类，权限规则保持不变。
- 查询、实际写入、缓存命中、幂等复用、预算拒绝形成不同操作事实，不重复计真实执行。
- 人工批准/拒绝、过期、策略撤销、多窗口重复点击，以及通知允许/拒绝都有一次有效决定和完整事件关联。
- MCP 合法调用、非法参数、未知工具、未授权、认证失败、GUI 不在线与超大帧均有相应受限接收记录；任何凭据/proof 不进入日志。
- 指定敏感字段和私钥文本在磁盘/WAL/临时文件/导出中不出现；解密只能取到脱敏版本。
- 长结果分页、截断标志、文件 diff、客户端/Provider 改名、重启和中断记录可追溯。
- 对话重命名/隐藏/重启保持会话用量；删除聊天与清理审计按最终批准的独立规则执行。
- 审计目录不可写、密钥不可用、记录中途失败和容量限制有可见反馈；不无声继续宣称记录完整。
