# 在线更新线路选择

> 状态：Review
> 最后更新：2026-10-30
> 关联：[验证与手动验收](../04-quality/update-routes.md)、[发布签名](../05-operations/update-signing.md)、[2.2.1 更新机制基线](../03-architecture/application-update.md)

## 范围与依据

用户要求参考“设计更新源测速与选择”会话，将相同选源逻辑接入 TinyShell 在线更新。已确认的参考规则为：每次检查前并行检测、自动择优、手动测速、固定及自定义线路、网络失败切换、可信清单校验。本次适配现有 Rust / Tokio / GPUI 更新器，保留 Windows、macOS、Linux 的选包和安装流程，不改变自动检查频率、通知规则，不自动下载或安装。

2026-10-30 用户明确要求自定义线路可逐条新增与移除，并补齐新增 / 保存反馈；据此将原单地址表单改为线路列表，保持原有信任校验和下载规则。

UI 使用 awesome-design-md / VoltAgent/awesome-design-md 的 sentry 风格，按项目主题、紧凑表单和 8px 间距适配。实现完成与验证通过分开记录；首次交付未获准本地编译、测试或启动应用，后续发布范围与结果见文末记录。

## 入口与交互

设置 → 在线更新增加“更新线路”：

| 模式 | 检测与下载规则 |
| --- | --- |
| 自动择优（默认） | 检测 GitHub、gh-proxy.com、ghfast.top，以及已保存的自定义代理；只保留最新可信版本、相同附件身份的线路，按响应耗时排序 |
| 仅 GitHub | 不请求第三方线路，沿用官方清单 / API / HTML 兼容路径 |
| 指定内置线路 | 只从该线路下载，失败不自动切到其他线路；无签名清单需要 GitHub 核验 |
| 自定义线路 | 逐条添加 HTTPS 代理前缀，再请求 `<前缀><完整 GitHub 附件地址>`；可固定使用任意一条、单独移除 |

自定义线路列表在所有模式下可见，地址输入框始终用于新增，不覆盖已有条目。点击“添加线路”或按回车后显示“正在保存…”，收到真实落盘成功回执后才显示新条目、清空草稿并提示“线路已添加并保存”。新增不自动切换当前模式；自动模式检测所有已保存线路。地址按 HTTPS URL 归一化，域名大小写、默认端口与结尾斜杠等同义写法不可重复，也不能重复添加内置地址。空输入禁用添加，非法或重复地址在表单下提示。

每行有“使用此线路 / 已选择”和“移除”；下载线路下拉也可直接选择每条自定义地址。使用统一确认弹窗移除，取消不改变配置；删除当前固定线路时在弹窗说明并在保存后切回自动择优，删除其他线路保持当前选择。长地址省略显示，列表悬停可查看完整地址。

新增、切换与移除均等待配置保存回执，再通过统一 Feedback 在发起窗口报告成功或失败。保存中禁用重复操作、测速及下载入口；失败恢复原列表与选择并保留输入，可重试；原窗口关闭后不将反馈投递到其他窗口。配置待保存期间其他窗口也显示已确认保存的列表，避免误以为排队已经保存。恢复旧值后重新标记配置待保存，以覆盖可能迟到的超时写入。

测速列表显示线路名称、响应耗时、可用 / 超时 / 不可用 / 校验失败 / 无法核验 / 版本落后。响应时间衡量本次小型清单及签名请求，不代表带宽或地理距离。

“重新测速”仅更新检测结果和检测时间，不写入 `update_last_checked_at`，不下载，不改变已检查版本对应的下载计划。每次真正检查都会重新探测。正在检测、下载或等待安装时禁用线路修改和再次检查；下载取消后可重新检查或改线路。已下载的安装文件不会再被自动检查覆盖。

更新弹窗显示检测状态、当前下载线路及失败后切换的线路。切换时进度从零重新开始。深浅色、中英文共用逻辑；原生窗口的空间和焦点行为待验收。

## 探测、可信性与选择顺序

1. 读取配置快照，使用异步 HTTPS 并行获取真实 `update-manifest.json`，单线路预算 4 秒，正文最多 2 MiB。测量从请求开始至清单 / 签名校验结束。
2. 校验 schema 1、版本、附件名、唯一文件名、固定仓库 URL、摘要。线路只包装固定的 GitHub 地址，不允许清单指定其他仓库。
3. 若构建内置公钥，请求对应版本的 `update-manifest.json.sig`，使用 Ed25519 验证原始清单字节。错误签名使该线路不可用，不将其视为旧的无签名清单。
4. 无签名发布，或未配置公钥的开发构建，第三方清单必须与 GitHub 的同版本、同名、同 URL、同哈希、同长度元数据一致；采用 GitHub 的元数据和说明。GitHub 无精确长度的历史 HTML 路径仍依赖哈希。
5. 没有可信结果且直连探测为网络故障时，最多再等待 10 秒，尝试既有 GitHub 兼容路径。直连的格式 / 校验错误不触发这次回退。有可信签名结果时不等待该回退。
6. 先比较可信版本，排除旧缓存，再按耗时选择线路。固定模式只允许指定线路进入下载计划。下载计划保存版本、附件地址、大小、摘要与候选线路顺序。
7. 新发布将纯文本说明内嵌在清单 `notes` 字段，随清单签名。旧清单缺少说明时，仅从 GitHub 补取，最多等待 4 秒，失败不影响有效更新。

四秒是单轮探测预算，不是整个操作保证四秒完成。需要 GitHub 回退和旧版本说明时总等待上限可增加。并行请求未来可按真实网络记录调整，但不将样例延迟当作性能承诺。

重定向限制为当前代理同源和明确的 GitHub HTTPS 分发域名，最多六跳，拒绝凭据和降级到 HTTP。自定义前缀禁止凭据、查询参数、片段、嵌套目标 URL，以及显式本机 / 私网 IP；这不是 DNS 防重绑定机制。第三方可看到用户 IP 与请求的公开更新路径，页面明确提示，并提供仅 GitHub 模式。

## 下载与异常

- 自动模式遇到连接 / 读取故障、超时、404、403、429、5xx 时，依次尝试本轮验证过的其他线路，每条最多一次。
- 每次重新从字节零开始，保留同一版本、大小和 SHA-256，不混合不同线路的部分内容。
- 长度、哈希、重定向策略、落盘或解压错误直接失败，不通过切换掩盖校验问题。
- 原有取消令牌和下载代次继续保护进度及结果；取消后的旧任务不能覆盖重试任务。
- 检测忙碌时不启动第二轮；配置快照发生变化时丢弃旧检测结果。测速结果只在内存中保存，重启不使用旧延迟。

## 配置与代码边界

本机配置使用 `update_routes: { mode, custom_prefixes, selected_custom_prefix }`，以归一化前缀作为条目标识。旧配置缺失时默认 `auto`；原单值 `custom_prefix` 自动迁移为列表，保留固定选择。显式空列表优先于旧字段，避免已移除条目复活。无效的历史地址保留可见供移除；固定选择缺失时回到自动模式。随现有偏好保存和合并，不纳入会话云同步协议；回退到仅支持单条线路的旧开发构建不会保留多线路选择，需要重新设置。输入草稿不立即写配置，点击添加后通过既有异步配置工作线程持久化并等待回执。

| 文件 | 职责 |
| --- | --- |
| `src/session/update_preferences.rs` | 配置、旧字段迁移、URL 归一化与列表操作 |
| `src/app/updater/routes.rs` | 线路包装、并行检测、信任归一化、排序与重试错误分类 |
| `src/app/updater/signing.rs` | 内置公钥和 Ed25519 验证 |
| `src/app/updater/release_source.rs` | 清单解析及 GitHub 兼容来源 |
| `src/app/updater/mod.rs` | 下载计划、按线路下载和既有校验安装流程 |
| `src/app/updater/route_ui.rs` | 异步检测编排、操作互斥、状态展示 |

| `src/app/settings/update_routes.rs` | 模式、地址、手动测速和线路表 |
