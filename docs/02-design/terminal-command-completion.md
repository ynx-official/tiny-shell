# SSH 常用命令补全与使用频次

> 状态：Review  
> 最后更新：2026-09-30  
> 关联：[文档索引](../README.md)、[同步架构](../sync/webdav-sync-architecture.md)

## 行为

- 普通 SSH 终端输入至少两个字符后，匹配常用命令的前缀。全部匹配项先按累计使用次数降序排序，再显示前 6 项；次数相同时保持命令库原顺序。
- 候选默认不选中。方向键选择，Tab 补全首项或已选项，Enter 接受已选项，Esc 关闭。接受候选只追加缺失内容，再按 Enter 提交才计数。
- 手输、单行粘贴和补全后的完整输入，在回车发送成功且与保存的命令一致时计一次。比较时忽略首尾空白，但保留大小写；不把带额外参数的输入归入较短的命令。相同正文对应多个命令 ID 时，各记录计一次。
- “提交”表示已向终端后端发送回车，不代表远端命令执行成功。只展示、选择或取消候选不计数；不从远程 shell 历史反推次数。
- 点击终端选择文本只隐藏候选，不丢弃已跟踪的输入，因此粘贴后点击终端继续输入仍能匹配完整前缀。粘贴跟踪与实际发送使用相同的转义字符和换行清理逻辑，空剪贴板不清除输入。
- 保持既有边界：只在普通 SSH 屏幕补全，不在本地终端、RDP 或 Vim/top 等备用屏幕补全；含 `[p1]` 至 `[p5]` 的参数模板不参与。多行粘贴、历史导航及无法准确跟踪的控制输入不作为完整命令统计依据。

## 保存和同步

`QuickCommand.usage` 是默认空的计数映射，随现有常用命令保存在本机配置中，重启保留。旧配置缺少此字段时按零次读取，不补记升级前的历史输入。

每个主窗口本次运行拥有独立随机写入 ID，仅递增自己的计数分量。合并时对同一写入 ID 取最大值，不同 ID 的分量求和。这让多窗口、多设备分别增加的次数能够合并，也使重复下载、重试或同步保持幂等；计数与求和采用饱和运算，避免整数溢出。映射分量随产生过提交的窗口运行次数增长，不自动删除仍可能被远端引用的分量。

本机保存合并已有命令的频次，避免较早的窗口快照覆盖较新的次数。删除命令仍删除该命令记录，不因频次合并重新创建。

WebDAV 和 S3 使用同一套 v3 payload，新增可选的 `quick_commands[].value.usage` 字段，不改变连接设置或对象路径。WebDAV 仍按现有保存防抖和自动对账流程同步；S3 仍使用现有手动同步入口。频次不包含额外的输入历史、命令参数记录或提交时间，只随已保存的命令同步计数映射。

三方合并先合并频次，再比较命令内容。只有次数变化不会产生编辑冲突，也不会阻止远端改名或删除；命令内容本身冲突时仍沿用原有确认流程。建议参与频次同步的客户端均升级到支持此字段的版本，旧客户端重新上传时可能丢弃未知字段。
