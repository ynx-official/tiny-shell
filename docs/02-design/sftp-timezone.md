# SFTP 文件时间与时区

> 状态：Review
> 最后更新：2026-10-21
> 关联文档：[文档索引](../README.md)、[主工作区设计](workspace-ui/design.md)

## 已确认行为

- 每次建立主 SFTP 连接并完成握手后，异步检测一次服务器时区。
- 成功时，文件列表的修改时间使用检测到的服务器时区。
- 检测期间及检测失败时，使用运行 TinyShell 的电脑本地时区。
- 刷新、切换目录、上传、下载、打开编辑器及重绘界面都不会重新检测。断开重连后重新检测一次。
- 文件列表表头上方始终显示当前时间显示规则，区分服务器、正在检测和本地回退。例如：`时区：服务器 · Asia/Shanghai (UTC+08:00)`。
- 时区名称按连接缓存，不持久化或同步。连接期间服务器更改时区后，需要重新连接才能更新。

## 检测与转换

通过同一条已认证 SSH 连接的独立 exec 通道执行只读探测，不向交互终端输入命令，不修改服务器时区或文件属性。

Unix 探测按以下顺序读取：命令环境中的 `TZ`、`/etc/localtime` 的 zoneinfo 链接、`timedatectl`、`/etc/timezone`。显式设置的 `TZ` 优先；为空表示 UTC，无法识别时直接回退本地，避免误用系统默认时区。

Unix 命令无法执行时，在同一次检测中尝试 PowerShell 7，通过 .NET 将系统时区转换为 IANA 名称。探测脚本使用 UTF-16LE EncodedCommand，避免 SSH 默认 PowerShell 再次展开脚本变量。正常 Unix 连接只执行一条探测命令；平台兼容探测最多执行两条，每条总超时为 3 秒，输出上限为 4 KiB，关闭通道另有 200 毫秒上限。

使用 `chrono-tz` 的 IANA 规则，将原始 Unix 时间戳转换成显示时间。每个文件按自己的日期应用夏令时规则，不能给所有历史文件统一加当前偏移。界面括号中的 UTC 偏移对应当前日期，悬停提示解释这一点。

原始 `mtime`、文件内容、断点续传的源文件检查和 MCP 返回的时间戳均保持原有语义。配置格式与保存位置不变，无迁移要求。

## 生命周期与异常

- 探测任务由当前 SFTP 运行任务持有；退出、关闭或连接失败时取消。
- 结果携带独立连接 ID，界面仅接受当前连接的结果，旧连接晚到的事件不会覆盖重连后的状态。
- 时区事件沿用可靠事件队列，避免一次性结果被高频普通事件挤掉。
- 禁止 exec、命令缺失、超时、输出超限、非零或缺失退出码、无效 UTF-8、未知时区及重复结果均按不可用处理，继续使用本地时区，不阻塞目录或传输。
- 当前仅接受可以映射到完整 IANA 规则的名称。时区缩写、单独的当前 UTC 偏移、自定义 POSIX 规则及 `right/` 闰秒时区不用于猜测服务器时区。

## 平台边界

- 客户端 Windows、macOS、Linux 均使用相同的服务器时区规则；本地回退由 `chrono::Local` 使用客户端系统规则。
- Linux/macOS 服务器优先使用标准 Unix 时区配置。只有复制后的 `/etc/localtime` 文件、没有可识别名称的系统可能回退本地。
- Windows 服务器需要可执行的 PowerShell 7，以及支持 IANA 转换的 .NET 6+ / ICU 环境；只有 Windows PowerShell 5.1、禁用相关转换或无法映射的服务器回退本地，不安装远程依赖。
- 查询的是独立命令环境中的时区；用户在交互终端内临时修改的 `TZ` 不会同步到探测通道。
- IANA 规则随应用依赖发布，不在运行时联网更新。服务器与客户端规则库版本差异可能影响近期调整过规则的地区。

## 手动验收

1. 连接使用 `Asia/Shanghai` 的 SSH 服务器，打开 SFTP：表头显示服务器时区与 `UTC+08:00`，文件修改时间与服务器默认时区下的 `stat` 一致。
2. 连续刷新、切换目录并上传下载：时区标识保持不变，服务器审计中不出现新的时区探测命令，既有文件操作正常。
3. 使用禁止 exec 的 SFTP 账号或无法识别时区的测试服务器：目录仍可浏览，探测结束后标明“本地”和“未获取到服务器时区”，时间与客户端本地规则一致。
4. 连接纽约等存在夏令时的服务器，查看冬季和夏季文件：各自使用对应日期的偏移，不统一按当前偏移换算。
5. 快速断开重连，或同时打开不同时区的两个连接：每次新连接单独检测，标签互不影响，旧结果不会覆盖新连接。
6. 缩窄文件面板并切换中英文、深浅主题：时区行不挤压或覆盖文件列，过长文本截断后可悬停查看完整内容。
