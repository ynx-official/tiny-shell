用户明确选择并要求处理工具描述、状态等待、会话管理、重复调用控制四项。未改变三种权限模式、目标授权、审批及远程文件版本校验。内置 AI 与外部 MCP 仍共用原 Engine；内置协调器承担会话和等待，外部继续保留十个工具和独立生命周期。

| 项目 | 原行为 | 本轮行为 |
| --- | --- | --- |
| 内置工具 | 十个 MCP 工具及生命周期参数 | 只读两项；受控/完全访问四项。模型只提供操作参数 |
| 状态等待 | 每 200ms 查询，每次加载连接配置 | 初次快照后等待通知，单次最长十秒；查询不加载连接配置 |
| 会话 | 模型建会话，跨轮历史保留已关闭 ID | 应用惰性建立并在同轮复用，结束/停止统一关闭；拒绝模型提供 ID |
| 调用控制 | 最多八次模型请求，可包含多个工具 | 保留八次模型请求，另限 16 次逻辑工具；重复无变化三次/不确定结果停止 |
| 读复用 | 相同读操作再次执行 | 一秒、最多四条的轮内读缓存，变更尝试前清空；变更结果不缓存 |
| 大结果 | 截断序列化后的字符串 | 缩短正文并保留合法 JSON 与版本/分页/退出码元数据 |

阈值 16/3/1 秒/4 条是本轮工程选择，预算不是新的权限配置；缓存命中也计入逻辑预算。外部 MCP 不应用这些内部阈值，沿用既有幂等和资源限制。

## 已运行证据

使用固定 Rust 1.96.1 和独立构建缓存 `target/rust-1.96.1`。以下都是本机模型 HTTP/SSE 替身与 Fake Remote，不产生收费模型请求或真实 SSH 操作。

- 原等待实现的三项回归先失败：不接受 wait_ms；十次任务查询额外加载十次连接配置。修复后三项全部通过，覆盖完成唤醒、任务归属、内部权限撤销及查询加载次数。
- 原工具集在两个回归中失败：只读/完全访问均暴露十个工具；修订为二/四个并隐藏应用持有的字段后通过。
- 调用预算和重复控制先用失败测试确认缺少边界，再实现总预算、短时读复用、重复结果停止及不确定变更拒绝。
- 工具步骤回归在旧错误优先逻辑下失败：not_executed 被显示成 Failed。修复后显式 Skipped/Unknown/TimedOut 保留。
- `cargo test --locked -p tiny-shell --bin tiny-shell ai:: -- --quiet`：**56 通过、0 失败、1 忽略**。忽略项是既有系统凭据专项，未将其计为通过。
- 上述 AI 测试包含：同一轮两个读复用一个会话、下一轮新建会话；重复读只执行一次；命令使后续读重新执行；18 次调用只执行前 16 次并保留所有结果配对；相同失败执行三次即停止；不确定命令执行一次后拒绝重放；模型传会话 ID 在 SSH 建立前拒绝；等待审批时停止而不执行命令；受控批准后完成命令及加密历史。
- 单命令受控闭环由“开会话 → 执行 → 总结”三次模型请求缩为“执行 → 总结”两次，Fake Remote 的实际命令仍恰好一次。两个操作一轮同样只有一个 SSH 会话；两轮回归共四次模型请求、两个会话、四次读。

以上计数来自确定性替身回归，不代表真实模型总调用下降百分比。中间编译失败和旧消息索引断言已修正；最终 AI 专项没有失败项。

## 手动验收

Linux SSH 的示例路径为 `/etc/os-release` 与 `/tmp`，其他远端平台需换成存在且允许读取的路径。

1. **只读模式**：在 MCP/CLI 设置的 AI 权限中选只读，新建绑定 SSH 的 AI 对话，发送“读取 /etc/os-release，并列出 /tmp”。工具记录应只有读取/目录业务步骤；没有列连接、开关会话或查询任务的模型步骤。继续发送执行命令的请求，模型不应获得命令/写入工具。
2. **受控与停止**：选受控，发送“执行 printf tiny-shell-check”。审批前没有命令执行；批准后只有一次命令结果。再发同类请求，在等待审批时停止对话，应进入中断且不执行待审批命令；人工终端可继续使用。
3. **会话管理**：完全访问下发送“依次读取 /etc/os-release，列出 /tmp”。两项操作正常完成且无需模型提供会话 ID。发送下一条消息应正常继续，不出现旧会话无效或重新查询历史 task_id 的循环。
4. **重复与预算**：发送“尝试读取同一个确定不存在的绝对路径四次”。相同失败三次后停止并总结未执行步骤。复杂请求触发单轮 16 次逻辑预算后也应总结，不声称剩余操作成功。工具记录中的未执行步骤显示跳过。
5. **读与变更**：对临时文本先读取、再重复读取；短窗口内结果一致。执行命令或写入后再次读取须取得新结果。连续两个相同命令仍分别执行，变更不因缓存被吞掉；远端断连/超时后结果显示未知/超时，不自动重放变更。
6. **外部 MCP**：重启客户端桥接以刷新工具描述；仍能发现十个工具。提交一个耗时任务后用 get_task 的 wait_ms=10000 查询，状态变化/审批/取消时返回；省略 wait_ms 的旧调用立即返回。权限撤销后不能继续查他人的任务或操作连接。
