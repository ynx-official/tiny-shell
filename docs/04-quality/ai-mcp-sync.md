## 实现与检查范围

已实现协议 v4 AI/MCP 域、本地隐私密码密钥库、旧系统凭据迁移、后台捕获与应用、配置保存防抖、按域三方冲突、密钥身份/地址绑定和密码重置接入。现有脏工作区中的预算、通知、审计等改动保留；本节记录发布前的功能实现阶段，该阶段没有升级应用版本、安装依赖、提交或推送。

新增回归测试：

- `src/ai/key_vault.rs`：未解锁拒绝保存、重开锁定、错误密码保留密文、密码轮换、损坏密文不覆盖。
- `src/ai/storage.rs`：无密码仅临时、持久化密文不含明文、重新解锁、不同地址不能读取原 Key。
- `src/ai/service/sync.rs` 与 `crates/mcp/tests/sync_policy.rs`：旧云同步结果不能覆盖新的本地模型配置、Key 或两类权限。
- `src/sync/automation/tests.rs`：SSH 密钥同步关闭时仍加密 AI Key、密码核验、拒绝密文跨身份/地址搬移、未变数据不反复上传、密码轮换、AI/MCP 独立合并、同域冲突、旧 v3 不删除新增域、未知版本拒绝和空设备首次同步恢复。

这些测试已加入代码，**未编译、未运行**，没有红/绿测试运行证据。项目 AGENTS.md 第 3 节规定用户明确要求前不运行 cargo test/check/clippy/build/run。

## 重点手动验收

用户随后于同日明确要求发版并跳过测试。Windows `cargo build --workspace --locked --release --no-default-features` 通过，包版本为 2.0.0；新增回归仍未编译或运行。版本资料校验通过，标签流水线和正式发布结果统一记录在 [v2.0.0 发布详情](../upgrade/v2.0.0/README.md)，不把发布构建当作下表的功能验收证据。

| 入口与步骤 | 预期结果及异常检查 |
| --- | --- |
| 设置 → 云同步：配置 WebDAV 和至少 8 字符的隐私密码；AI → 模型服务：保存测试服务商、模型及 Key；MCP 设置：修改模式、指定连接授权和 AI SSH 开关；立即同步 | 远端写入 schema_version 4，包含 AI 与 MCP；原文中没有 API Key。连接、托管密钥和快捷命令仍可同步。 |
| 第二台更新后的设备：同一 WebDAV、正确隐私密码，立即同步或远端恢复 | 恢复服务商、模型、默认项、预算、通知和两类权限；发起一次用户明确选择的模型测试可使用恢复后的 Key。客户端仍须独立配对，聊天和审计不迁移。 |
| 第二台设备先输入错误密码，再输入正确密码 | 错误密码阻止上传，恢复时不能读取或覆盖已有 AI Key；改正后可解锁并保存，重启继续使用已记忆密码。 |
| 未设置隐私密码：新建服务商并填写 Key，测试，然后退出重启 | 本轮临时 Key 可用；没有普通配置明文落盘，重启提示配置密码或重新输入 Key。无秘密的 AI/MCP 设置仍能同步。 |
| 关闭“同步密码和密钥”，保持正确隐私密码并同步带 Key 的 AI 服务商 | SSH 秘密不上传，AI Key 仍是密码加密密文；另一设备仍必须使用正确隐私密码解锁 AI Key。 |
| 两台设备分别修改 AI 预算和 MCP 模式；再同时修改不同 AI 预算值 | 不同域自动合并；同 AI 域生成冲突，选本地/远端后应用对应预算与 Key。冲突列表不展示明文 Key。 |
| 同步拉取期间保存新的 AI 服务商或 MCP 授权 | 旧结果不能覆盖新保存；显示待同步/失败后重新对账，必要时产生真实冲突。 |
| 用隔离测试配置更改服务商地址，或损坏远端 Key 密文 | 原 Key 不发送到新地址。密文损坏的上传被阻止；恢复保留本地 AI 配置，原密钥文件不被空值覆盖。 |
| 本机只有 AI 服务商：云同步 → 强制重置隐私密码，然后重启并在另一设备用新密码恢复 | AI 密钥用新密码重加密，旧密码不能解开。锁定的本地密钥必须先解锁，不能假装恢复成功。检查远端成功、本地写入失败时的失败提示与手动恢复。 |
| 从已有 v3 同步文件升级，随后使用旧客户端 | 新版读取旧数据并保留本地 AI/MCP，下次写入 v4；旧客户端拒绝 v4，不覆盖新增配置。 |
| 启用 WebDAV 自动同步，连续保存设置；用仅有 AI/MCP 的隔离配置重复立即同步；另测 S3 手动同步 | 保存触发防抖；隔离配置没有变化时不新增 PUT；S3 手动入口同样包含新域。SSH 等既有域按原自动对账清单回归。 |
