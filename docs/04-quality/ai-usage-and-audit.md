## 2026-10-13 用量状态回归

后续首轮自动命名已接入，四轮 HTTP 回归现在实际多服务一次独立标题请求（合成用量 5 tokens），最终共 5 次模型请求、已知总量 60；继续验证历史未知保留、进行中等待、真实零值和取消不清零。命名归属首轮，第二轮工具审计不关联标题请求；新增证据见 [AI 自动标题验证](ai-conversations.md#2026-10-13-首轮后台自动标题)。以下保留命名功能加入前的已执行检查记录。

用户反馈“1 次用量未知”在继续回复后变为 0。根因是汇总只看 usage 是否完整，未区分进行中请求；尚未返回 usage 时先计入 unknown，尾帧到达又移出 unknown，界面同时缺少独立累计请求数并固定展示零未知。

- 红灯证据：新增真实本机 HTTP/SSE → runner 测试，第一轮仍等待 usage 时断言 unknown 为 0，旧实现实际为 1，稳定失败。
- 修复：分别统计已确认、等待返回、结束后未知；保留真实零值和已观察分项，聊天与审计共用汇总规则。界面显示累计请求数，零未知/零等待不展示。复用已有审计终态索引，无数据迁移或历史重写。
- 跨轮验证：同一会话连续执行缺失 usage、40 输入 + 15 输出、真实 0 用量、取消四轮；结束后的累计请求数依次为 1/2/3/4，已知 Token 为 0/55/55/55，未知数为 1/1/1/2。重复 usage 尾帧不重复计数。每轮解密重读实际聊天文件并比对独立审计汇总。
- 补充覆盖：部分字段、完整零值、用量先于结束到达、数据库关闭重开、晚到 pending 不覆盖终态、实例恢复后等待转中断未知，以及零状态文案不展示。变更的中英文资源键均存在且唯一。

## 运行中发现并修正的问题

- rusqlite 数字读取改用可校验的有符号整数转换，拒绝负数用量索引；修正 UI trait、下拉菜单返回类型、示例类型导入及 Clippy 问题。
- 已删除聊天的审计筛选原先被较新的工具事件抢先填为内部 ID。现在先读取模型标题快照，再回退到 ID；保留当前聊天的重命名结果。回归先失败、修正后通过，原生菜单复验显示合成会话标题。
- 审计独立窗口缺少统一确认框的渲染层，原生点击 JSON 导出没有出现确认框。现在在公共 Render 外层渲染，覆盖详情和设置分支。GPUI 回归验证两个页面的执行/取消按钮可见、取消关闭且不导出/清理；先失败、修正后通过。UI 回归隔离后台查询，避免真实存储线程唤醒 GPUI 的确定性测试调度器；存储与查询另由领域测试和原生预览覆盖。

- 详情：命令参数中合成密码为 `[REDACTED]`；160 行标准输出在受限高度内滚动；普通文件修改前/后及统一 diff 脱敏展示。
- 筛选与排布：会话标题快照下拉、按会话筛选、四个页签、窄窗口详情及正文导出确认框检查通过；留存默认 90 天、512 MiB，只读检查布局。
- CSV：通过原生保存框导出当前页 6 条合成摘要，脚本核对已知 300/40/340 用量、外部 `excluded` 和无合成秘密。
- JSON：通过原生确认框及保存框导出所选命令的完整 4 条时间线，脚本核对批准渠道、退出状态、标准输出，以及所有参数密码已脱敏。导出成功也产生管理审计事件。
