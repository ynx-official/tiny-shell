## 首次交付的回归代码与历史记录

用户随后确认：只在下方添加了模型，没有选择顶部默认组合。因此保存提示符合原校验，但缺少就近选择入口。现已增加保存时的联动选择表单；取消保留编辑，已有有效默认时直接保存。获取列表采用已添加状态标记和提交前禁用校验，覆盖当前组件库仍允许用键盘确认禁用行的情况；共享行标记使过滤后的结果也同步更新。

2026-10-22 用户运行 `cargo run` 后报告两处 E0599：厂商列表和模型表格调用 `overflow_y_scroll`，但对应模块未导入 `StatefulInteractiveElement`。此前已核对锁定的 GPUI 源码并补齐导入；模型表格现已取消独立滚动，因此 `providers/view.rs` 不再需要该 trait。本轮全目标编译检查未再出现此错误。

同日用户截图显示：发现模型选择器下方留白过大，四个已添加模型仅显示一行多，底部说明接近被裁切条目。静态核对锁定的 gpui-component 源码后确认，Select 外层使用 `size_full()`，只对 Select 调用 `.small()` 不能限制外层高度；同时模型列表存在可收缩的嵌套滚动区域。已为三个选择器添加明确高度的外层、让已添加模型跟随页面滚动、长 ID 和完整默认组合换行，并为下拉长名称补充悬停提示。发现模型添加后清空选择器的选中状态。原生效果仍待手动验收。

- `src/ai/model/defaults.rs`：跨厂商默认组合唯一性、同名模型身份、空或非法选择、停用和删除约束、旧格式兼容及新旧会话隔离。
- `src/ai/service/provider_settings_tests.rs`：厂商与默认组合一起持久化、删除当前默认厂商失败时保留 Key、无效保存不覆盖文件、保存替代默认后允许删除。
- `providers/default_picker.rs`、`providers/discovery.rs`：未选模型不能提交、选择但未保存不修改原表单、已添加项不可提交、移除后恢复、搜索条件下标记同步。表单测试另覆盖缺少默认时打开选择表单与取消保留编辑，已添加状态随添加和移除更新；均已通过编译检查，未运行断言。
- `src/app/settings/ai/providers/tests.rs`：编辑厂商与默认选择独立、同名厂商按 ID 区分、切换厂商清空模型、停用厂商排除、移除默认模型后清空选择。保留已有表单通知稳定性和大型模型列表搜索回归；补充发现模型触发框高度、四行模型与底部说明不重叠、长 ID 换行、完整默认组合摘要及重复添加后重置选择器的断言。这些测试代码已通过 `cargo check --all-targets` 的编译检查，但未执行，尚无红/绿测试结果。

## 手动测试清单

入口：设置 → AI → 模型服务。以下均需用户后续自行构建/运行后检查，本轮代理未运行应用。

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 多厂商展示 | 配置至少两个厂商，搜索名称，再清空搜索；逐项点击左侧列表 | 名称、模型数量、启用状态准确；右侧随编辑对象切换，顶部默认不变 |
| 默认联动与唯一性 | 顶部选择另一厂商，展开模型列表；选一个模型并保存 | 旧模型选择先清空；只列所选厂商模型；保存后全局仅一个组合，只有对应行有默认标记 |
| 同名模型 | 两厂商都添加相同模型 ID，分别切换默认厂商 | 必须重新选模型；新会话使用所选厂商的连接，不因模型同名混用 |
| 新旧会话与重启 | 更换默认并保存；创建新会话，回看旧会话；重启后再看设置 | 新会话继承新组合；旧会话保持原模型；重启后默认和启用状态保留 |
| 未保存切换 | 修改 URL、名称或输入 Key，点击另一厂商；分别尝试取消和放弃 | 取消保留当前编辑；放弃后切换、丢弃厂商草稿和输入 Key；全局选择草稿保留或提示需重选 |
| 非法或缺少选择 | 只添加模型或切换默认厂商后不选模型即保存；输入非法 URL 或空名称再保存 | 缺少默认时弹出联动选择表单；选择模型并点击“选择并保存”后一起保存；非法 URL 或空名称仍显示错误且不覆盖已保存配置 |
| 保存引导与取消 | 保存弹窗中先取消；再次保存，切换厂商、选择模型并保存；已有有效默认时直接保存配置 | 取消保留编辑及原默认；切换厂商清空模型；只能提交有效组合；已有默认时不重复弹窗，重启后保留新选择 |
| 停用默认厂商 | 还有其他启用厂商时停用当前默认并保存；再选择其他组合后保存 | 未选替代时拒绝保存；选定替代后保存成功；停用厂商不出现在默认选择器中 |
| 删除默认模型 | 移除默认模型，尝试保存，再选择剩余模型后保存 | 无默认时拒绝保存；新选择保存后唯一生效；没有模型的厂商不能保存 |
| 删除默认厂商 | 从右侧更多菜单删除当前默认；再选择其他厂商为默认并保存后重试 | 有可用替代时首次拒绝且不清 Key；替代保存后可删除。删除最后一个可用厂商后显示未配置默认 |
| 添加与刷新模型 | 分别手动添加和从获取列表添加模型；取消工具调用后保存并重新打开；重复添加该 ID | 两种新增方式均默认勾选工具调用；取消后保存并重开仍未勾选；重复 ID 不重复添加或覆盖能力设置；已有模型状态保留；不自动更换全局默认 |
| 截图场景回归 | 保留 4 个模型，刷新列表，再关闭下拉框；上下滚动设置页面 | 选择框下方没有大块空白；4 行均可完整查看；最后一行不被说明或高级选项覆盖 |
| 完整名称与窄窗口 | 添加接近 256 字节的长模型 ID，选为默认，缩窄窗口并增加界面字号 | 已添加模型 ID 和顶部完整组合自然换行；默认标记、工具开关、删除按钮互不遮挡；恢复宽窗口后布局正常 |
| 下拉选择 | 搜索位于长列表末尾的模型，用方向键和 Enter 选择；再次展开，试 Esc 和点击外部取消；悬停长名称 | 搜索和键盘定位有效；取消不提交新选择；长名称悬停显示完整 ID；菜单不超出窗口 |
| 连续发现与添加 | 搜索一个未添加模型并选中，再次展开搜索另一个；对已有模型分别尝试鼠标与回车；移除后再展开 | 每次添加后恢复占位提示；已有项显示勾选和“已添加”，重复确认不增加条目；移除后可重新选择；搜索中的标记实时更新，全局默认不被添加操作改写 |
| 长列表与操作定位 | 添加 20 个以上模型，滚动页面至最后一行，修改工具调用、移除最后一项 | 所有模型可通过页面滚动访问；操作只影响对应行；底部说明和保存按钮可访问 |
| 凭据与请求边界 | Key 留空保存；清除 Key 取消/确认；测试连接；用错误地址测试失败 | 留空保留 Key；清除沿用确认；测试提示费用并显示结果；失败可恢复编辑，默认不被改写 |
| 高级项与展示 | 展开/折叠高级选项；切换中英文、深浅主题、调整窗口，使用长名称/长模型 ID 和较多条目 | 高级值不因折叠丢失；HTTP 确认仍可取消；字段、按钮和表格无重叠，列表可滚动，英文无明显溢出 |

初次使用、所有厂商停用和最后厂商被删时，应显示无可用默认的说明，不创建虚假的默认模型。已有配置升级后，应恢复原默认厂商和其有效模型；原来其他厂商的默认模型不显示为第二个全局默认。
