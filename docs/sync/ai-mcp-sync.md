# AI 与 MCP 配置云同步

> 最后更新：2026-10-12

## 已确认范围与变更原因

2026-10-12 用户确认将 AI 服务商、模型、默认服务商与模型、执行预算、通知设置以及 MCP 权限接入现有云同步。API Key 在本地和云端均使用云同步的**隐私信息加密密码**保护；这与 WebDAV 登录密码是两个独立凭据。已保存的隐私密码沿用本机硬件绑定密文，在启动时自动解锁；未配置时新 Key 仅在内存中临时使用。

本次替代旧 AI-12 中“API Key 仅保存系统凭据库、不参与同步”的规则。聊天历史、历史加密主密钥、独立审计、客户端配对令牌、客户端注册信息、任务、活动 SSH 会话和审批结果仍只属于本机。

## 同步内容与协议兼容

同步文件仍为 `tiny-shell-sync.json`，写入协议升级为 `schema_version = 4`，读取支持 v3 和 v4。WebDAV 自动对账与手动同步共用原有管线；S3 的手动同步也复用该协议。

- `ai` 是单个 `ai-settings` 实体：公开的服务商与模型设置、执行预算、通知偏好，以及按服务商 UUID 保存的密钥状态。
- `mcp` 是单个 `mcp-permissions` 实体：外部启停、模式、范围、授权摘要、已知目标摘要，以及内置 AI 的独立 SSH 启停与模式。机器上的 Policy revision 与内部能力代数不复制，由本机 setter 更新。
- AI 与 MCP 分别进行三方比较，同一域在两端发生不同编辑时生成冲突。不同域的编辑可以自动合并。删除全部模型以空服务商列表表达，协议中缺少 `ai` / `mcp` 字段不表示删除。
- 首次无 baseline 对账时，空配置的设备采用云端设置；已有模型列表保留本地同 UUID 条目，并补入云端其他服务商。首次 MCP 本地仍为默认关闭、只读、指定连接且没有授权时采用云端权限，否则沿用本地配置。后续对账由 baseline 决定变化及冲突。

所有参与该同步目标的设备都应更新到支持 v4 的客户端。旧客户端只接受 v3，看到 v4 会拒绝同步，避免忽略新增字段后覆盖云端。新客户端读取旧 v3 后保留本地 AI/MCP 配置，下次成功上传写入 v4。旧客户端无法直接同步已经升级的文件；回退应用前应保存云端与本地配置备份，不能通过删掉新版字段继续共同写入。

## 密钥加密与解锁

复用现有 `Argon2id + XChaCha20-Poly1305` 原语，不增加依赖或另一套密码。

本地 `ai/keys.enc` 存储认证加密后的密钥映射，每个记录包含服务商 ID、Base URL 与 Key。读取必须通过密码解锁，并核对 ID 和地址；仅改变 `providers.json` 的地址不能使原 Key 发送到新地址。`ai/providers.json` 不含 Key。

云端 Key 仅输出 `encrypted`、`empty` 或 `omitted` 状态，禁止 AI 的旧明文状态作为密钥导入。非空密文中的 ID 与 Base URL 同样必须匹配服务商配置。密文损坏、密码错误或身份不匹配时保留本地 Key；上传预检会阻止覆盖未能解密的远端 Key。手动恢复在隐私密码缺失、错误或 AI 密文损坏时保留本地 AI 配置，界面报告密码或不可用字段。

恢复未能应用 AI 域时不推进 baseline，也不记为完整同步成功。这样保留的本地旧配置不会在下一次自动对账中被误认为用户新编辑并覆盖云端。

“同步密码和密钥”开关继续控制连接密码与 SSH 密钥。AI Key 独立于该开关：只要有有效隐私密码，就加密并同步；没有密码时不会输出明文 Key。服务商、预算、通知和 MCP 配置本身不含认证秘密，可以在没有 Key 时同步。

隐私密码输入与强制重置入口始终可见，自动同步始终读取已保存的密码，关闭 SSH 秘密同步不会让 AI 密钥失去解锁密码。启用自动同步先用当前表单进行一次对账，仅在远端密码校验及本地密钥保存成功后记忆密码，避免未验证的输入覆盖密钥库所需的旧密码。

未改变的 AI 密钥复用经过身份、地址及明文核验的旧密文，隐私密码不变时复用原校验值，避免随机 salt/nonce 造成 AI 配置反复上传。密码更换后重新生成密文。

## 旧系统凭据迁移

启动时只有已保存的隐私密码才会触发本地解锁与迁移。首次云同步先读取远端并校验隐私密码，再读取旧 API Key；预检中的旧 Key 只留在内存，不在上传前删除系统凭据。

成功应用同步或启动时的迁移先原子写入密码加密文件，再删除已迁移的旧 API Key 项。删除失败会报告错误，原系统项仍保留；一旦密码密钥文件存在，它就是权威来源，旧系统项不再作为读取回退，防止旧值复活。历史加密密钥继续使用系统凭据库。

## 保存、并发与失败

AI 设置与密钥保存、MCP 权限保存会推进各自配置代次并触发原有 3 秒防抖。聊天流式更新、任务状态及通知回调不会被当作配置保存。同步结果携带本地配置代次；后台应用前再次校验，已经保存的新配置不能被旧结果覆盖。

AI 文件和原配置文件分别原子写入，并复用 AI 串行持久化锁；它们与 MCP / 主配置 / baseline 之间没有全局事务。AI 导入先保存设置，再更新绑定地址的密钥；密钥写入失败会尝试恢复设置，旧密钥文件保持原状。任一存储、权限应用或 baseline 写入失败都报告同步失败，不能记为完整成功。其他独立存储可能已经写入，需要重新对账；失败不会重放 SSH 操作或恢复审批。

权限通过原有 Engine setter 应用，取消对应来源的旧任务、会话及审批，并记录 `cloud_sync / synchronization` 审计来源。授权仍绑定连接摘要，目标发生改变不能继承旧授权。同步不会配对新客户端。

## 隐私密码重置

沿用设置页原有强制重置确认入口，使用本机当前已解锁 Key 和配置重新加密并覆盖云端，然后更换本地密钥库密码及保存的密码。只有 AI 服务商而没有 SSH 秘密时也能进入重置。

存在锁定的本地密钥文件时，必须先用保存它时的密码解锁，不能将空 Key 当成恢复结果覆盖云端。忘记密码无法从密文恢复 API Key，需要备份或重新取得服务商密钥。远端上传、本地密钥重加密和主配置记忆密码是独立写入；远端已变更而本地写入失败时会报告失败，需使用新密码恢复/重新对账，不能假定全部步骤已完成。
