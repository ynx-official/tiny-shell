# WebDAV 配置自动对账与三方合并架构

> 状态：Review
>
> 最后更新：2026-08-18
>
> 当前协议：`schema_version = 3`

## 1. 目标与边界

TinyShell 使用一个统一的自动对账协调器处理配置同步，不分别维护“自动上传”和“自动下载”定时器。WebDAV 自动同步以及设置页的“立即同步”始终复用同一条管线：

```text
拉取远端 → 读取 baseline → 三方比较 → 合并或生成冲突 → 必要时条件推送 → 保存本地配置和新 baseline
```

自动对账由以下事件触发：

- 首个工作区窗口启动时立即执行一次；
- 本地配置成功持久化后 3 秒防抖；
- 窗口重新激活，30 秒内最多检查一次；
- 窗口在至少 2 分钟的休眠/空闲间隔后恢复；
- 用户配置的周期检查，设置单位为分钟，默认 5 分钟；
- 网络类失败或 ETag 条件写冲突后的有界退避重试。

WebDAV 支持自动对账。S3 继续保留手动“立即同步”和恢复入口，但使用相同的 baseline、三方合并和冲突规则。

## 2. 协调器状态

协调器使用单调递增的本地变更代次跟踪 dirty：

1. 配置成功保存后递增 `local_change_generation`。
2. 对账开始时记录本次处理的代次。
3. 只有完整成功后才推进 `reconciled_generation`。
4. 同步期间出现的新保存会设置 `pending_automatic`；旧同步成功不能清除这些新变化。
5. pending 在当前操作结束后合并为一次新对账，不为每次保存启动独立同步。

失败重试从 5 秒开始指数退避，最长 5 分钟。身份验证、缺少密码等需要用户处理的错误不会自动反复重试。WebDAV 不提供统一可靠的推送机制，因此分钟级轮询是实时性和请求开销之间的可配置折中。

## 3. 无变化跳过上传

序列化会生成新的顶层 revision、时间、设备 ID 和实体版本，因此不能直接比较完整 JSON。内容等价比较忽略这些传输元数据，但保留所有同步业务字段、删除时间、密码校验器和秘密字段状态。

如果合并候选与远端内容等价：

- 不发起 PUT；
- 应用合并后的本地配置；
- 保存远端 ETag、成功时间和精确远端 payload 作为新 baseline；
- 仍按完整同步成功处理 pending 代次。

## 4. Baseline 与安全边界

baseline 存储在配置目录的 `sync-state.json`，按规范化同步目标哈希隔离。其内容包括：完整 v3 远端 payload、revision、ETag、协议版本和成功同步时间。

文件使用现有硬件绑定加密机制，采用临时文件、`sync_all` 和原子替换；Unix 平台临时文件权限为 `0600`。损坏、设备密钥不匹配或写入失败时返回错误，不静默删除旧 baseline。

冲突对象可能在内存中持有连接密码或私钥内容，因此：

- 不实现包含实体值的 `Debug` 输出；
- UI 只读取实体类型、稳定 ID 和名称标签；
- 不把冲突实体写入日志或未加密的辅助文件；
- 冲突解决完成前不上传远端。

## 5. 三方合并

每个实体分别比较 `baseline / local / remote` 的同步内容，不使用时间戳替代内容判断：

| Local 相对 baseline | Remote 相对 baseline | 结果 |
| --- | --- | --- |
| 未变 | 未变 | 保持 baseline |
| 已变 | 未变 | 使用 Local |
| 未变 | 已变 | 使用 Remote |
| 已变 | 已变且内容相同 | 使用共同结果 |
| 已变 | 已变且内容不同 | 生成冲突，不上传 |

当前实体范围包括 SSH 连接、托管密钥、连接分组、快捷命令分类和快捷命令。

连接和托管密钥按稳定 ID 比较；非空 fingerprint 仍用于跨设备密钥去重和引用规范化。快捷命令移动分类属于命令实体内容变化。

## 6. Tombstone 决策

活动实体、删除实体和缺失状态共同参与三方比较：

- 一侧删除、另一侧未变：保留删除；
- 两侧均删除：保留 tombstone，不因删除时间不同产生冲突；
- 一侧删除、另一侧修改或恢复：生成冲突；
- baseline 中存在、合并结果中缺失的托管密钥、分类或命令：自动生成 tombstone；
- 已存在且仍未恢复的 tombstone 原样保留，避免每次同步推进删除版本。

本版本不清理历史 tombstone。保留周期、设备确认水位和永久删除属于后续运维策略。

## 7. 冲突体验

设置页显示冲突实体列表和安全标签。用户可以保留本地版本、使用远端版本、把本地连接复制为新连接，或对全部剩余冲突应用同一策略。

“复制为新连接”会为本地连接生成新 ID，并让原 ID 使用远端版本。所有冲突解决后重新执行内容等价判断和条件上传；如果选择结果与远端一致，不产生无意义上传。

冲突等待期间发生新的本地保存会使旧冲突上下文失效，并基于最新本地配置重新对账。

## 8. 并发与失败恢复

- 已存在远端对象使用 `If-Match`；新对象使用 `If-None-Match: *`。
- `412` 或等价远端冲突不会强制覆盖，会在退避后重新拉取和三方合并。
- 任一上传、配置持久化或 baseline 持久化失败都不会把本次操作记为完整成功。
- pending 只表示需要再次对账，不复制同步任务或远端凭据。
- 手动“使用远端恢复”保留为故障恢复入口，不属于自动协调器的常规路径。

## 9. 已知限制

- 连接分组的实体 ID 当前由分组名称稳定派生，重命名表现为删除旧分组并新增新分组。
- 尚未定义 tombstone 自动清理与多设备确认水位。
- 网络恢复目前由同步失败退避重试驱动，没有独立依赖操作系统网络可达性事件。
- 配置文件中的旧 `sync_interval_hours` 会在加载时转换为 `sync_interval_minutes`；新版本仍保留小时字段的向后兼容值，旧客户端读取时不会失去可用的同步配置。
- 真实 WebDAV、S3、双设备离线编辑和多平台 UI 仍需要发布前手工验收。
