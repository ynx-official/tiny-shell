# Windows 界面闪烁问题分析与修复报告

## 1. 问题概述

Windows 环境下曾出现以下体验问题：

- 启动和关闭软件时短暂闪出窗口。
- 调整界面字体、终端字体时出现卡顿或闪烁。
- 切换右键复制/粘贴、关键字高亮、显示隐藏文件等开关时闪烁。
- SFTP 展开目录、切换选项或折叠面板时出现整窗刷新感。
- 部分设置看起来需要关闭设置弹窗后才完全生效。

这些现象由三个问题叠加造成：

1. Windows 控制台子进程产生真实的系统窗口闪现。
2. 配置加密和磁盘写入阻塞 UI 线程。
3. 应用存在不必要的整窗重绘，部分设置的运行时更新顺序不合理。

## 2. 根因分析

### 2.1 reg.exe 和 wmic.exe 造成系统级闪窗

配置文件包含 SSH 密码、代理密码、托管密钥和连接信息。项目在提交 c0a954e 中加入了硬件绑定加密：

1. 获取当前机器的稳定标识。
2. 使用 Argon2 从机器标识派生密钥。
3. 使用 XChaCha20-Poly1305 加密配置文件。

旧实现通过以下外部命令获取 Windows 机器标识：

    reg query HKLM\SOFTWARE\Microsoft\Cryptography /v MachineGuid
    wmic csproduct get uuid

TinyShell 使用 Windows GUI 子系统运行，本身没有控制台窗口。但 GUI 程序启动 reg.exe 或 wmic.exe 时，Windows 可能为子进程短暂创建控制台窗口，从而出现肉眼可见的黑窗闪烁。

该查询会在以下场景触发：

- 软件启动时读取并解密配置。
- 修改设置后保存配置。
- 软件关闭时保存窗口布局和配置。

因此启动、关闭以及大量设置交互都会出现相似闪窗。

### 2.2 配置加密和磁盘刷写阻塞 UI

旧设置回调普遍直接调用 ConfigStore::save。

一次保存包含：

- 查询机器标识。
- Argon2 密钥派生。
- 配置序列化。
- XChaCha20-Poly1305 加密。
- 创建临时文件。
- 写入并执行 sync_all 强制刷盘。
- 原子替换原配置文件。

这些操作原本全部发生在 GPUI 界面事件回调线程中。用户点击一次字号按钮或开关，界面必须等待完整加密和磁盘写入结束后才能绘制下一帧。

表现包括：

- 按钮或开关短暂无响应。
- 弹窗内容突然整体重绘。
- 字体变化延迟出现。
- 用户感觉必须关闭弹窗后设置才生效。

### 2.3 空闲事件泵定期强制整窗重绘

主事件泵原本每 16ms 检查一次状态，并在完全空闲时大约每秒主动调用一次 cx.notify。

光标闪烁、系统指标动画和后端事件现在都有独立的刷新条件，因此这个空闲兜底刷新已经没有必要。它会放大透明标题栏、滚动条、弹窗和复杂布局的视觉变化。

### 2.4 设置持久化与运行时应用耦合

部分设置原来的执行顺序是：

1. 修改配置缓存。
2. 同步加密保存。
3. 更新 GPUI 主题或运行时字段。
4. 通知界面刷新。

例如界面字体大小只有在同步保存完成后才会更新全局主题。保存较慢时，用户看到的就是延迟变化或弹窗关闭后才明显生效。

## 3. 修复方案

### 3.1 使用 Windows 注册表 API

Windows 下不再启动 reg.exe 或 wmic.exe，改为使用 winreg 直接读取：

    HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Cryptography\MachineGuid

该方式不会创建控制台子进程，因此不会产生黑窗。

### 3.2 缓存机器标识

使用 OnceLock 缓存机器标识，每个进程只读取一次注册表。后续配置读取和保存直接使用内存中的值。

这样既保留了原配置加密兼容性，也消除了重复系统查询。

### 3.3 设置即时生效，持久化后台执行

设置交互调整为：

1. 立即更新 TinyShell 运行时字段。
2. 立即更新主题、终端渲染或开关状态。
3. 立即通知 GPUI 重绘。
4. 在后台线程加密并保存偏好设置。

已覆盖：

- 界面字体大小和终端字体大小。
- 界面字体和终端字体。
- 光标样式、主题和语言。
- 右键复制/粘贴和关键字高亮。
- 布局锁定和监控区域位置。
- 代理开关和代理参数。
- 侧栏折叠。
- SFTP 面板折叠和隐藏文件显示。
- 快捷键设置。

### 3.4 后台保存串行化并丢弃过期任务

后台保存使用全局递增序号和互斥锁。保存前检查任务是否仍是最新任务。

连续快速调整字号时，旧保存任务会被跳过，只保留最新偏好，避免并发覆盖和重复重加密。

### 3.5 仅合并偏好字段

后台保存不会使用当前窗口的完整配置覆盖磁盘配置。

保存前会重新读取磁盘中的最新配置，只合并界面偏好字段，保留：

- SSH 连接列表。
- 连接分组。
- 会话数据。
- 托管密钥。
- 传输记录。
- 其他窗口刚保存的数据。

新增测试验证偏好合并不会覆盖连接数据。

### 3.6 窗口关闭时同步兜底

关闭窗口时仍会同步保存一次最新偏好，确保后台任务尚未完成或程序快速关闭时不会丢失设置。

同步操作发生在退出流程，不再阻塞普通按钮和开关交互。

### 3.7 删除空闲整窗重绘

移除了事件泵中每秒一次的空闲 cx.notify。

现在仅在以下情况重绘：

- 收到终端或后端事件。
- 系统监控数据变化。
- 指标动画仍在进行。
- 光标到达闪烁时间。
- 用户交互主动改变界面。

### 3.8 修复更新脚本窗口标志

Windows 更新脚本原来标注为 CREATE_NO_WINDOW，但实际使用的是 0x00000008，该值是 DETACHED_PROCESS。

现已改为真正的 CREATE_NO_WINDOW：

    0x08000000

避免自动更新脚本执行时产生控制台闪窗。

## 4. 为什么原测试没有发现

原有测试主要验证：

- 配置能否正确加密和解密。
- 配置保存是否原子替换。
- 设置值是否正确更新。
- SFTP 和终端逻辑是否正确。

测试不会检测 Windows 是否短暂创建了控制台窗口，也不会评价 UI 线程被阻塞几十或几百毫秒后的视觉体验。

因此功能测试可以全部通过，但安装包实际操作仍可能闪窗。

这类问题需要结合：

- 外部命令审计。
- UI 线程阻塞审计。
- Windows GUI 实机验证。
- 设置更新链路检查。

## 5. 是否不可避免

不是不可避免。

以下问题都可以彻底避免：

- 后台工具产生的黑色控制台窗口。
- 设置点击时同步加密造成的卡顿。
- 无状态变化时的周期性整窗重绘。
- 设置必须关闭弹窗后才更新运行时状态。

正常且不可完全消除的只有真正需要的局部重绘，例如：

- 文件列表内容变化。
- 字体大小变化导致布局重新计算。
- 展开目录导致目录树增加节点。
- 切换主题导致颜色更新。

这些重绘应该是稳定的一次性布局更新，不应出现额外窗口、黑窗或连续闪烁。

## 7. 后续开发规范

1. Windows GUI 程序不得直接启动可能创建控制台的后台命令。
2. 必须启动后台命令时使用正确的 CREATE_NO_WINDOW。
3. 优先使用系统 API 或 Rust 库代替 reg、wmic、PowerShell、CMD 查询。
4. GPUI 点击、输入、拖拽回调中不得执行 Argon2、压缩、大文件 I/O 或 sync_all。
5. 高频设置应采用运行时即时更新、后台合并保存。
6. 后台保存必须串行化，并处理旧任务覆盖新状态的问题。
7. 不得在空闲状态下周期性调用整窗 cx.notify。
8. 新增 Windows 外部命令时必须进行闪窗审查。
