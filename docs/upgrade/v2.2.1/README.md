## 版本概述

本次补丁修正 Windows 安装版在线更新的执行与提示，并处理关闭外部 MCP 后桥接进程持续驻留的问题。安装过程改为可见向导，明确区分下载完成与安装完成；MCP 桥接从握手阶段开始检查开关和客户端注册，关闭或撤销后自行退出。用户要求本次正式发布跳过测试，构建与发布结果单独记录。

## 改进与修复

### Windows 安装更新

- 下载完成显示“更新已下载，等待安装”，不再提前提示安装完成。更新窗口和设置页使用一致的安装类型文案；Windows 安装版按钮为“立即安装”，其他类型为“安装并重启”。
- 安装确认提醒保存工作并等待文件传输结束。确认后关闭当前应用，在原安装目录启动可见的安装向导；完成页的启动选项由安装器处理，辅助进程不重复启动应用。
- 安装器记录独立详情日志，辅助进程记录退出码和版本核对结果。只有安装器成功退出且原目录程序版本符合目标版本，才清理本次下载包和辅助脚本，日志继续保留。
- 安装取消、中止、失败或要求系统重启时保留安装包；不自动重启系统，不将未验证的安装报告为成功。安装器启动失败或版本不匹配时提供错误提示和日志位置。
- 启动安装辅助进程失败时，在原窗口显示操作失败反馈，并保留已下载包与重试入口。脚本使用 UTF-8 BOM 和路径转义以支持中文及特殊字符路径。

### MCP 桥接退出

- 外部 MCP 关闭时，独立 helper 与主程序的备用入口均在创建运行时及 stdio 传输前退出；客户端重复重连不再留下持续运行的新桥接。
- 握手进行中及连接完成后，每 500 ms 检查所属配置的总开关与客户端注册。检测到关闭、撤销或不可读配置后结束服务，并限制传输清理和运行时关闭的等待时间，避免客户端持有输入管道时无限等待。
- 每个桥接只观察自己的配置与注册，不按进程名批量结束其他实例；不同配置及同配置其他有效客户端保持独立。
- 补充双入口进程生命周期回归代码和 Windows 安装辅助脚本回归；常规 Windows CI 接入安装脚本回归。本次发布按要求不执行测试。

## 行为与界面变化

Windows 安装版的在线更新依次为“下载更新”“等待安装”“立即安装”，随后显示正常安装向导。仅关闭并重新打开应用不会自动安装已下载更新。Windows 便携版、macOS 和 Linux 的安装执行机制保持原样，共用文案明确为安装并重启。

关闭外部 MCP 后，外部客户端可能显示连接断开；重新启用后需要由客户端重新连接。第三方客户端自行重试时仍可能出现立即退出的短暂进程。内置 AI 的独立权限、普通终端连接及主应用服务保持原有行为。

## 配置与数据兼容性

本次不修改配置 schema、客户端注册格式、工具接口、存储路径、连接数据、密钥加密、会话历史、审计格式或云同步协议，无数据迁移。Windows 安装目录、安装标识和用户安装模式沿用现有配置。

可回退到 v2.2.0，无专属数据回退步骤；旧版将恢复此前的安装更新和桥接驻留行为。升级前可按既有方式备份配置。

## 升级说明

可从 v2.2.0 直接覆盖安装。保存工作、结束传输并退出旧进程后，安装或替换程序，再重新启动应用和外部 MCP 客户端。

已经运行的旧版仍使用旧的在线更新代码。若旧版在线安装失败，请从官方发布页下载对应安装包，手动覆盖安装一次；新安装向导逻辑在更新后的程序中生效。旧桥接进程需要通过所属客户端断开或重启清理，本次代码更新不会自动改写已运行的旧进程。

Windows 提供 x86_64 安装包与便携包；Linux 提供 x86_64 AppImage 与压缩包；macOS Apple Silicon 和 Intel 均提供基础版及 RDP 版安装包与便携包。MCP 生命周期修复适用于三个平台。

## 破坏性变更与已知问题

没有新增破坏性配置或数据变化。关闭 MCP 或撤销注册将主动断开对应客户端，这是本次修复的预期行为。

本次按用户要求跳过测试，真实安装向导、旧版在线升级、MCP 进程退出及多平台原生交互尚未验收。既有 Windows 更新专项文档中的早期脚本测试与 2.2.0 本地构建记录，不代表本次 2.2.1 完整验证通过。

## 重点手动验收

1. 更新窗口及设置 → 在线更新：下载完成后显示等待安装；Windows 安装版点击立即安装，取消确认时会话保持不变，安装包可重试。
2. Windows 原目录含空格或中文：确认安装后显示向导，覆盖安装保留配置，完成页勾选启动只启动一次；取消或失败时保留安装包及日志。
3. 设置 → MCP / CLI → 外部 MCP：保持客户端连接，关闭总开关，检查新版本桥接在五秒内退出；禁用时反复重连无持续驻留，重新启用后能正常发现工具。
4. 同时连接两个客户端，仅撤销其中一个，检查另一客户端仍可使用；独立 helper 与主程序备用入口行为一致，不同配置目录互不影响。
5. Windows 便携版、macOS 和 Linux：检查下载完成文案和安装并重启流程，验证普通终端及内置 AI 仍可正常使用。

## 线上更新说明

TinyShell v2.2.1

Windows 安装版在线更新改用可见安装向导，沿用当前安装目录覆盖升级。安装完成后由向导决定是否启动应用，避免重复启动；取消或失败时保留安装包，并保存更新日志和安装详情日志，便于重试和排查。

下载完成准确显示“更新已下载，等待安装”。Windows 安装版使用“立即安装”，其他安装类型使用“安装并重启”。启动安装失败时保留已下载包和重试入口，不再混淆下载完成与安装完成。

修复关闭外部 MCP 后桥接进程持续驻留的问题。桥接在握手和已连接阶段均检查开关与客户端注册，关闭或撤销后主动退出；禁用时客户端重复重连不会留下持续运行的新桥接。重新启用后需由客户端重新连接。

可从 v2.2.0 直接覆盖安装，无需迁移配置和会话数据。若旧版在线安装失败，请手动下载安装包覆盖安装一次；旧客户端和桥接进程应在升级后重启。

本次按要求跳过测试，真实安装及多平台交互尚待手动验收。
