## 版本概述

TinyShell 2.0 将模型对话和受控自动化接入现有终端工作区：可以在应用内配置 AI 服务商、流式对话并调用 SSH 工具，也可以为外部 MCP / CLI 客户端单独配对和授权。新增会话用量与独立加密审计，用于查看模型请求、工具操作和审批过程。AI 与 MCP 配置纳入云同步，API Key 在本地及云端都必须使用云同步隐私密码解锁。同步写入格式升级至 v4，因此采用新的主版本号。

## 新功能

### 内置 AI 对话与执行控制

- 支持配置服务商、Base URL、模型与默认模型，在终端工作区发起流式对话、查看 Markdown 与工具步骤，并管理本机聊天历史。
- 内置 AI 的 SSH 开关与权限模式独立于外部 MCP；工具执行仍受连接授权、只读或受控模式以及审批规则约束。
- 支持配置工具调用与模型请求预算。达到预算或需要审批时暂停，用户可以继续或终止；已经完成的步骤不会因继续操作自动重放。
- 暂停通知可配置。Windows 与 macOS 支持通知中的决定入口；Linux 通过应用内入口处理决定。通知回调与当前任务身份及审批状态关联。

### MCP / CLI 桥接与权限管理

- 增加 stdio MCP helper，并支持使用应用自身的 MCP 入口；安装包随应用提供 helper。
- 客户端独立配对，支持持久化命名、撤销和权限配置。可按指定连接或全部连接设置只读、受控及完整模式。
- 提供连接发现、远端读取、文件操作及命令任务接口；任务支持查询、等待、取消和审阅。授权绑定目标摘要，连接目标变化不会继承旧授权。

### 会话用量与操作审计

- 在 AI 历史和对话底部查看模型请求用量，区分输入、输出、缓存、推理和总量。服务未返回用量时显示未知，不推算、不重复累计；外部 MCP 工具操作不计为模型 Token。
- 设置 → AI → 统计与审计，以及 MCP / CLI 任务页可打开独立窗口，筛选会话、来源、时间和状态，查看请求、审批、参数、输出与文件差异。
- 审计使用本机密钥加密 SQLite 存储，支持脱敏 CSV 摘要和经确认的 JSON 详情导出。默认留存为 90 天、512 MiB，可配置保留周期、容量及脱敏规则。
- 审计存储不可用时阻止新的变更操作，不明文回退，也不自动重试远端动作。聊天删除与审计清理独立，重启后的中断操作标记结果未知。

### AI 与 MCP 配置云同步

- WebDAV 自动和手动同步包含服务商、模型、默认项、执行预算、通知偏好、外部 MCP 权限及内置 AI 的独立权限。S3 手动入口复用同一协议。
- API Key 使用云同步的隐私信息加密密码加密；该密码与 WebDAV 登录密码相互独立。关闭 SSH 的“同步密码和密钥”开关后，AI Key 仍使用隐私密码加密同步。
- 本地密钥保存在 `ai/keys.enc`，复用 Argon2id 与 XChaCha20-Poly1305，并绑定服务商 ID 和地址。已记忆的隐私密码自动解锁；未配置密码时新 Key 只在内存中临时使用。
- 首次同步、三方比较、冲突选择和配置保存防抖均接入既有管线；旧同步结果不能覆盖同步期间刚保存的新配置。
- 密码错误或密文损坏时阻止危险覆盖，未完整应用 AI 配置时不记为完整同步成功。隐私密码输入和强制重置入口始终可见。

## 改进与修复

- 改进终端输入、连接管理、SSH 编辑及会话窗口交互，统一使用项目确认弹窗。
- 流式对话开始后减少重复状态提示，优化工具步骤展示与暂停后的操作反馈。
- 更新为用户选定的圆润黑白终端图标，同步 Windows、macOS、Linux 安装资源及 README 展示。
- Rust 工具链固定为 1.96.1；工作区增加 MCP helper，平台打包同步携带对应二进制。

## 行为与界面变化

主工作区增加 AI 对话入口；设置增加 AI 模型、执行预算、通知、统计与审计，以及 MCP / CLI 客户端、权限和任务管理。云同步恢复可以改变这两类权限，并取消对应来源的旧任务、会话和审批；配对令牌、聊天历史、运行任务、审批结果和审计记录继续留在各自设备上。

AI 密钥不再仅依赖系统凭据库。升级后必须配置或沿用已保存的云同步隐私密码，才能持久化并解锁 API Key；没有隐私密码的新 Key 退出后不会保留。

## 配置与数据兼容性

- 同步文件仍为 `tiny-shell-sync.json`。新版读取 v3/v4，成功上传写入 `schema_version = 4`，新增 `ai` 与 `mcp` 实体；v3 缺少新实体不会删除本地 AI/MCP 配置。
- **旧版客户端只接受 v3，不能同步已经升级的 v4 文件。所有共享同一同步目标的设备必须一起升级。** 不得仅删除新增字段后让旧客户端继续共同写入。
- 已保存隐私密码或同步验证通过后，旧系统凭据中的 API Key 会迁入密码加密文件；先原子保存，再清理旧项。密码文件成为权威来源，系统旧项不作为读取回退。
- 现有 SSH 会话、连接、快捷命令、托管密钥和硬件绑定的本机密码记忆机制继续使用既有存储。AI 聊天历史主密钥与审计主密钥仍由本机系统凭据库管理。
- 多个存储之间没有全局事务。部分写入成功后另一步失败会报告失败，需要重新对账；不会因此重放 SSH 操作。

## 升级说明

1. 升级前备份本地配置目录和 WebDAV/S3 的同步文件，保留可用的隐私密码及服务商密钥恢复方式。
2. 更新共享同步目标的全部设备，完全退出旧进程后重启新版本。首次同步后云端格式升至 v4。
3. 在设置 → 云同步配置正确的隐私信息加密密码，再检查 AI 模型服务和两类权限；第二台设备用同一隐私密码恢复。
4. 忘记隐私密码无法从密文恢复 Key。只有本机已解锁且仍持有 Key 时才能用强制重置重新加密，否则需重新取得服务商密钥。

Windows 提供安装包和便携包；Linux 提供 AppImage 与压缩包；macOS Apple Silicon 和 Intel 分别提供基础版与 RDP 版的安装包及便携包。源代码构建需 Rust 1.96.1；操作系统凭据库及 GUI/FreeRDP 依赖按已有平台要求安装。

## 破坏性变更与已知问题

- v4 同步格式及 API Key 持久化规则为本版本的兼容性边界。回退旧应用前需恢复升级前的本地与云端备份；旧应用无法读取新的密码密钥文件或 v4 同步文件，不能假设直接覆盖安装即可恢复全部能力。
- 新增同步回归已写入代码，本次按用户要求跳过测试；真实双设备 WebDAV/S3、模型服务、跨平台原生通知和权限变更仍需手动验收。构建成功仅证明构建与打包过程，不代替功能运行验证。
- 云端覆盖与本地密钥重加密是独立写入。密码重置若云端已成功而本地失败，应使用新密码恢复或重新对账，不能继续假定旧密码有效。
- macOS 图标由系统处理外层材质，原生显示仍可能随系统版本变化；本次不启动各平台应用核对桌面图标。

## 重点手动验收

| 入口与步骤 | 预期结果与异常关注 |
| --- | --- |
| 云同步 → WebDAV：正确隐私密码，保存 AI 服务商与 Key，修改 MCP 权限，再同步；第二台新版设备恢复 | 设置与 Key 恢复，云文件无明文 Key；错误密码不能解锁或覆盖已有 Key，配对及历史仍在本机。 |
| 关闭 SSH 秘密同步后同步 AI Key；重启，再测试隐私密码重置 | AI Key 仍加密同步，已记忆密码自动解锁；新密码可恢复，旧密码不能解开。无密码临时 Key 退出后消失。 |
| 两台设备分别修改 AI 与 MCP，再同时修改同一 AI 预算 | 不同域合并，同域提示冲突；同步期间新保存的设置不能被旧结果覆盖。 |
| AI 对话 → 工具审批、预算暂停、继续/终止及系统通知 | 权限与预算决定对应当前任务；继续不重放已完成动作，流式输出与用量展示正常。 |
| 统计与审计 → 筛选、详情、CSV/JSON 导出及留存设置 | 用量未知标记明确，敏感字段脱敏，外部 MCP 不计 Token；确认取消不导出，不重试远端动作。 |
| MCP / CLI → 配对、重命名、指定连接授权、撤销；既有 SSH/SFTP 操作 | 客户端身份及权限独立，撤销取消对应任务；连接管理、文件传输和旧同步域无回归。 |
