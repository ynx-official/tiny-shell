# TinyShell v1.1.10

> 发布日期：2026-07-30

## 版本概述

本版本修复在线更新检查依赖 GitHub 未认证 API 导致的 403 限流问题。更新器现在使用稳定更新清单、GitHub Releases API 和发布页面三级来源，在共享网络或 API 临时不可用时仍能获取最新版本，并继续使用 SHA-256 校验下载内容。

## 改进与修复

- 优先读取随 GitHub Release 发布的 `update-manifest.json`，直接获得版本、资产地址、精确大小和 SHA-256，日常更新检查不再消耗 GitHub API 配额。
- 兼容没有更新清单的旧版本：清单不存在时继续请求 GitHub Releases API。
- GitHub API 返回 403、429、服务端错误、连接失败或超时时，自动通过 GitHub 最新发布跳转和资产页面获取版本及校验信息。
- HTML 兜底会校验发布标签、下载域名、资产路径和同一资产条目中的 SHA-256，拒绝摘要缺失、格式错误或跨版本资产。
- GitHub API 错误现在保留响应正文和限流重置时间，便于判断实际失败原因。
- 更新检查失败时不再更新“上次检查时间”，避免临时网络错误被记录为一次成功检查。

## 行为与界面变化

- 用户主动检查更新的入口和更新安装流程保持不变。
- 当 GitHub API 配额耗尽或临时不可用时，应用会自动切换到发布页面兜底，不再直接显示 403 错误。
- 更新检查成功后仍按原配置记录检查时间；失败后应用重启可以重新尝试。
- 本版本没有新增设置项或用户可见文案。

## 配置与数据兼容性

- 配置格式、会话数据、连接、密钥、同步、SFTP 和快捷键数据均未变化，无需迁移。
- 更新清单属于发布资产，不写入用户配置或本地持久化数据。
- Windows 安装版与便携版、macOS 安装版与便携版、Linux 发布包继续按原有资产命名规则选择。
- 可回退到 `v1.1.9`，但旧版本仍可能在共享出口网络下受到 GitHub API 每小时未认证请求配额限制。

## 升级说明

可以直接覆盖安装，无需修改配置。首次发布 `v1.1.10` 后，发布流水线会同时上传 `update-manifest.json`；后续版本的更新检查将优先使用该清单。

## 破坏性变更与已知问题

- 本版本没有破坏性配置或数据变更。
- HTML 解析只作为旧发布或 GitHub API 不可用时的最终兜底；如果 GitHub 同时调整发布页面结构，且目标发布又没有更新清单，兜底检查仍可能失败。
- 更新清单损坏、版本不匹配或 SHA-256 非法时会直接拒绝更新，不会静默降级到可信度更低的数据源。

## 验证结果

根据本次发布要求，未执行本地格式检查、Clippy、Rust 测试、Python 测试和 release 构建。Windows、macOS 与 Linux 的构建及发布元数据校验将由 `v1.1.10` 标签触发的 GitHub Actions 发布流水线执行；本文件不将这些尚未执行的项目记录为已通过。
