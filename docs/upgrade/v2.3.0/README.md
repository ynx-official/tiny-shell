## 版本概述

本次版本为在线更新增加线路检测、自动择优和多条自定义线路管理。应用在每次检查前重新检测，只从可信的最新版本中选择线路；自动模式下载遇到网络故障时可切换已验证的备用线路。发布清单和内嵌更新说明增加 Ed25519 签名，安装包继续校验长度与 SHA-256。用户要求本次正式发版跳过测试，构建及实际发布结果另行记录。

## 新功能与改进

### 更新线路选择

- 设置 → 在线更新新增更新线路区域，支持自动择优、仅 GitHub、固定内置线路和固定自定义线路。自动模式检测 GitHub、两条内置代理及已保存的自定义线路。
- 每次启动、定时或手动检查都会重新检测，显示可用、超时、校验失败、无法核验及版本落后等状态。先选择可信的最新版本，再按响应耗时排序，避免优先使用响应快的旧缓存。
- 提供手动重新测速，仅刷新检测结果和检测时间，不更新时间调度、不下载，也不覆盖已确定的下载计划。显示的耗时是小型清单与签名请求耗时，不是下载带宽。

### 多条自定义线路与操作反馈

- 自定义 HTTPS 代理前缀可以逐条新增、选择和移除。新增后保留当前模式，自动模式会检测所有已保存线路；固定模式使用选中的一条。
- 地址归一化后防止同义地址及内置地址重复添加；非法地址在表单中说明原因，空输入无法添加。移除操作使用统一确认框，移除当前固定线路会在保存后回到自动择优。
- 新增、切换和移除均等待实际保存回执，再在发起窗口显示结果。保存失败恢复原列表与选择并保留草稿，保存期间防止重复操作和冲突检测。

### 可信清单与下载保护

- 发布清单继续使用 schema 1，新增内嵌纯文本说明与独立 Ed25519 签名附件。公钥编译进应用，私钥仅供发布签名步骤使用；第三方线路不能提供新的信任公钥。
- 有效签名可独立验证清单身份；旧的无签名发布仍需要 GitHub 权威元数据核验。错误签名、附件身份不一致或校验失败的线路不会进入下载计划。
- 自动模式遇到连接、读取或服务状态故障时，按本轮验证结果切换备用线路，每条最多一次，从字节零重新下载；版本、附件、长度和摘要保持一致。
- 大小、哈希、重定向、落盘或解压错误直接报告失败，不通过切换线路掩盖。固定线路失败不自动切到其他线路。
- 下载中和等待安装时保护已有任务及载荷，禁止再次检查或修改线路；取消后可重新操作，旧任务不会覆盖新任务的进度。

## 行为与界面变化

在线更新默认采用自动择优模式。界面增加线路选择、自定义地址列表、保存反馈、测速结果和当前下载线路；网络故障切线时提示新线路并从零显示进度。现有检查频率、通知偏好、下载确认和安装确认保持原有规则，不自动下载或安装。

自动模式会向第三方线路请求公开更新资源，线路运营方可看到用户 IP 和请求路径；可选择“仅 GitHub”避免请求第三方线路。单线路探测预算为四秒，旧发布兼容回退和补取说明可能延长整个检查时间。

## 配置与数据兼容性

新增本机更新偏好 `update_routes`，包含模式、自定义前缀列表和所选前缀。旧版配置缺失该字段时默认自动择优；开发版单值 `custom_prefix` 可迁移为列表，显式空列表不会复活已移除的旧值。固定选择缺失时回到自动模式。

连接、密钥、会话历史、审计和云同步协议没有格式变化。线路偏好不加入会话云同步。旧客户端可忽略清单新增的说明字段，继续读取 schema 1；旧的无签名 Release 保留 GitHub 核验路径。

可覆盖安装 v2.2.1，无需手工数据迁移。回退到 v2.2.1 后不提供新线路功能，旧版再次保存配置时可能丢弃新增偏好；回退前应备份配置，自定义线路可能需要重新设置。正式签名公钥需要稳定维护，密钥轮换不在本次范围内。

## 升级说明

保存工作并等待文件传输结束，退出旧版本后覆盖安装并重新启动。首次进入设置 → 在线更新，按网络需要选择自动择优或仅 GitHub；需要自定义线路时逐条添加 HTTPS 代理前缀。

Windows 继续提供安装包与便携包；Linux 提供 AppImage 与压缩包；macOS Apple Silicon、Intel 均提供基础版与 RDP 版安装包和便携包。各平台选包、安装向导及重启流程保持不变。新线路能力从更新后的程序开始生效，旧版本仍使用旧的检查下载逻辑；旧流程不可用时可手动下载安装包覆盖安装。

## 破坏性变更与已知问题

没有新增破坏性数据迁移。默认自动检测第三方线路会改变更新请求的网络目的地，可通过仅 GitHub 模式控制。第三方可用性与耗时随网络环境变化，当前排序不保证实际下载速度最快。

本次跳过测试，原生窗口、真实网络故障切线、多窗口保存反馈和各平台安装流程仍待手动验收。签名验证发布身份，不单独证明全网最新，也不替代 Windows / macOS 平台代码签名。自定义地址限制不是 DNS 防重绑定机制。

发布前已确认仓库尚无所需公钥变量和私钥 Secret，必须完成首次独立签名密钥配置后才能推送发布标签；不能跳过签名门禁。

## 重点手动验收

1. 设置 → 在线更新：检查自动择优和仅 GitHub 模式，核对线路状态及选中版本；重新测速不改变上次检查时间，也不开始下载。
2. 添加两条不同 HTTPS 代理，确认成功提示后列表与重启结果一致；重复地址被拒绝，移除当前固定线路时确认切回自动，取消确认不改变配置。
3. 下载时模拟首条线路网络失败，自动模式从零切换可信备用线路；固定模式保持失败，哈希错误直接终止。
4. 下载完成等待安装时再次检查或改线路，确认已下载包和安装入口保持有效；取消与重试不出现旧进度覆盖。
5. 在隔离环境检查签名、错误公钥、清单修改和旧无签名发布；结合专项验收文档检查 Windows、macOS、Linux 的选包及安装流程。

## 线上更新说明

TinyShell v2.3.0

在线更新新增线路检测与自动择优。每次检查都会重新检测 GitHub、内置加速线路和已保存的自定义线路，先选择最新可信版本，再按响应耗时选择下载线路。也可以固定使用某条线路，或选择仅 GitHub。

自定义 HTTPS 线路支持逐条添加、选择和移除，保存完成后再显示结果。重复或非法地址会明确提示，保存失败保留原列表和输入草稿。手动重新测速不会改变检查调度或开始下载。
