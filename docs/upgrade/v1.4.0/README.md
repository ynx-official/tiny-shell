# TinyShell v1.4.0

> 发布日期：2026-08-06

## 版本概述

本版本重点强化多窗口运行时的一致性和可恢复性。配置保存、对话框、终端工作区与后端事件现在具有明确的生命周期和状态边界，减少多窗口并发、连接重连、跨窗口拖拽和异步回调造成的状态错乱。同时继续拆分应用层职责，统一用户可见文案与结构化状态表达。

## 改进与修复

- 所有应用窗口共享同一个配置仓库和保存队列；保存前比较磁盘配置、上次成功快照和当前来源，拒绝陈旧窗口覆盖更新后的配置。
- 窗口关闭按顺序保存完整配置和布局，再释放窗口 lease；配置、布局和仓库关闭错误统一聚合并可观测。
- 对话框协调器保存完整的待打开请求，支持打开、单槽排队、最新请求替换和强制替换；对话框 token 隔离旧关闭回调与旧异步结果。
- 工作区状态集中到明确的数据边界，跨窗口转移标签组时只从转移 pane 的有效标签恢复活动状态，不再引用目标窗口旧 pane。
- 关闭 pane、标签组或窗口时同步清理终端事件路由、待处理事件、系统信息和 SFTP handle，避免后台状态悬挂。
- 终端后端事件增加连接代际和全局序号；重连后丢弃旧代际事件，并按序号协调控制队列与输出队列，保证更早的输出不会被关闭事件越过。
- 保留有界输出队列的背压策略，控制事件在输出拥塞时仍可送达，避免 UI 线程被无限数据积压拖垮。
- 同步失败展示改用结构化运行时状态，不再依赖本地化字符串前缀；补齐连接、对话框、设置和错误路径的中英文文案。
- SSH 终端启动参数收敛为明确的请求对象，减少应用层与后端层之间的参数扩散。
- 更新优化路线文档，并为配置持久化、对话框状态机、跨窗口转移、事件路由、重连代际及跨队列顺序补充回归测试。

## 行为与界面变化

- 多个窗口同时修改和关闭时，较旧的窗口状态不会再静默覆盖较新的配置。
- 同一时刻只显示一个应用对话框；不同类型的新请求会排队，必须替换当前对话框的流程会显式执行替换。
- SSH 重连后，只处理当前连接代际产生的状态与输出；关闭事件仍会等待更早产生的输出被处理。
- 同步失败横幅的颜色和状态由真实运行时结果决定，不受当前界面语言或翻译模板影响。
- 终端、SFTP、连接管理和更新入口保持原有主要操作方式，无需重新配置快捷键或连接。

## 配置与数据兼容性

- 配置文件路径及现有会话、分组、托管密钥、同步、SFTP 和终端偏好格式保持兼容，不需要数据迁移。
- 本版本调整的是保存冲突检测和运行时生命周期，不改变同步协议及敏感数据加密格式。
- 如需回退到 `v1.3.2`，可直接安装旧版本；建议在回退前正常退出所有 TinyShell 窗口并备份配置文件。

## 升级说明

Windows、macOS 和 Linux 用户均可直接覆盖安装并重启 TinyShell，无需额外迁移。升级前应先关闭所有正在运行的 TinyShell 窗口，避免旧进程在升级后继续写入配置。

## 破坏性变更与已知问题

没有已知的配置或数据破坏性变更。终端输出队列仍采用有界背压：极端持续高输出且消费端长时间拥塞时，超出容量的普通输出可能被拒绝，但关闭等控制事件会继续得到处理。
