# TinyShell v1.3.0

> 发布日期：2026-08-03

## 版本概述

本版本新增 FinalShell 连接迁移能力，可从 FinalShell 备份 ZIP 中保留 SSH 连接信息和原始目录层级，同时明确隔离外部软件中的密码与私钥材料。导入后的连接在首次使用时补录密码或选择 TinyShell 托管密钥。版本同时整理设置窗口结构，并集中改进配置持久化、同步合并、异步任务、终端事件和发布构建的稳定性。

## 新功能

- 连接管理器的导入入口现在区分“从 TinyShell 导入”和“从 FinalShell 导入”。
- FinalShell 导入直接读取 ZIP，不将内容解压到磁盘；支持保留嵌套分组、连接名称、主机、端口、用户名、认证类型和最近访问时间。
- 导入前提供连接数、分组数、密码认证数、密钥认证数和跳过项目数预览，确认后再统一写入配置。
- FinalShell 密码字段、私钥内容和 `secret_key_id` 不参与反序列化、解密或持久化。
- 密码认证连接首次打开时要求输入密码；密钥认证连接首次打开时要求选择 TinyShell 托管密钥，保存后继续连接。

## 改进与修复

- FinalShell ZIP 文件名支持 UTF-8，并兼容常见的 GBK 中文路径。
- 导入器拒绝路径穿越和不安全路径，并限制最多 2000 个条目、单个连接 JSON 1 MiB、总声明大小及实际读取 JSON 32 MiB。
- ZIP 解析移到后台执行器，避免较大备份阻塞窗口交互；导入错误按类型映射为中英文用户提示，底层错误保留在日志中。
- 相同 FinalShell 密钥连接完成凭据补录后再次导入时会被识别为重复项，不再生成重复连接。
- 所有已保存连接入口统一执行凭据门禁；SSH 与 SFTP 后端同时拒绝空密码和待选择密钥状态，避免其他入口绕过首次补录。
- 普通 TinyShell 密钥连接继续保留使用显式密钥、托管密钥或 `~/.ssh` 默认密钥的既有行为。
- 设置窗口将原有选项拆分为外观、终端和工作区页面，代理、同步、更新等表单状态也按职责重新组织。
- 配置写入使用统一序列和后台保存边界，降低并发偏好保存覆盖较新完整配置的风险。
- 后台任务、自动同步、更新下载和搜索状态使用明确的代次与取消机制，被替换或关闭的任务能够及时停止。
- 终端输出会在不跨越状态事件的前提下合并连续数据；传输进度、SFTP 延迟和远程系统信息只保留队列中的最新更新，减少高频刷新。
- 同步合并为连接、托管密钥和删除记录建立索引，改进大连接目录下的合并性能，并保持重复合并结果稳定。
- HTTP 代理 CONNECT 响应现在校验完整响应头、HTTP 版本和 2xx 状态码，不再通过响应正文中的模糊文本判断成功。
- release 构建使用 `panic = "abort"` 和多代码生成单元，另提供 `release-fast` 配置；依赖补丁采用仓库内固定副本以提高构建可重复性。
- CI 在 Linux 增加 release 模式测试，发布工作流和 macOS 打包脚本统一使用 `--locked` 构建。

## 行为与界面变化

- 连接管理器工具栏和上下文菜单的导入命令变为两个明确选项，原有 TinyShell 加密归档导入流程保持不变。
- FinalShell 导入窗口先选择 ZIP 并展示预览，只有确认后才修改本地配置；保存失败时不会应用部分导入结果。
- 导入连接缺少凭据时会打开连接凭据窗口。密码模式自动聚焦密码输入；密钥模式要求选择已导入 TinyShell 的托管密钥。
- 设置窗口导航中不再使用单一“常规”页承载全部常用选项，相关设置分别位于外观、终端和工作区页面。
- 高频终端输出、监控和传输事件可能以更少的 UI 更新批次呈现，但终端字节顺序、状态事件顺序和最终进度保持不变。

## 配置与数据兼容性

- 从 `v1.2.0` 升级时，现有会话、分组、密码、托管密钥、代理、同步、终端、SFTP 和快捷命令配置无需迁移。
- 配置新增可序列化认证状态 `key-pending`，只用于标记尚未选择 TinyShell 托管密钥的外部导入连接；完成选择并保存后会转换为普通 `key` 状态。
- FinalShell 密码和密钥材料不会进入 TinyShell 配置、原生连接归档或同步数据；只有连接元数据及待补录认证状态会进入现有配置流程。
- 原生 TinyShell 连接归档和配置同步会保留 `key-pending` 状态，使连接在其他设备上仍需明确选择当地可用的托管密钥。
- `v1.2.0` 不认识 `key-pending`。若配置中仍有待选择密钥的连接，直接回退可能导致旧版无法读取配置；回退前应在 `v1.3.0` 中为这些连接选择密钥，或恢复升级前备份。

## 升级说明

可以从 `v1.2.0` 或更早版本直接覆盖安装，无需执行配置迁移。建议在首次使用 FinalShell 导入前保留现有 TinyShell 配置备份，导入窗口只会追加有效连接和缺失分组，不会导入 FinalShell 凭据。

Windows、macOS 和 Linux 使用相同的 ZIP 解析与连接迁移逻辑。当前提供的 FinalShell 备份来自 Windows，并包含 GBK 中文目录；其他平台选择该 ZIP 时无需先手工转换文件名或解压。

需要回退到 `v1.2.0` 时，请先确认不存在仍为“待选择密钥”的导入连接。可以在 `v1.3.0` 中逐个选择托管密钥并保存，或者关闭应用后恢复升级前的配置备份。

## 破坏性变更与已知问题

- 本版本没有面向升级流程的破坏性配置迁移，但包含上述旧版本无法识别的 `key-pending` 回退限制。
- FinalShell 导入仅处理支持的 SSH 连接 JSON，不迁移端口转发、终端个性化设置、历史命令、密码、私钥或其他 FinalShell 专有数据。
- 密钥认证连接不会自动匹配本机 `~/.ssh` 私钥；为避免错误使用其他密钥，必须在首次连接时明确选择 TinyShell 托管密钥。
- 密码在首次补录并选择“保存并连接”后会按 TinyShell 现有会话保存规则持久化；导入动作本身不会读取或保存 FinalShell 密码。
- 超过安全限制、包含不安全路径、文件名编码无法识别或没有支持连接的 ZIP 会被拒绝，不会进行部分导入。
