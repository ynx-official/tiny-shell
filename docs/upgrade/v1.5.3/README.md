# TinyShell v1.5.3

> 发布日期：2026-08-15

## 版本概述

本版本集中改进多窗口终端工作流：标签可多选并在窗口之间移动或合并，也可拖放到工作区边缘创建分屏；同时将模态框和操作反馈收敛到正确的原生窗口，减少多窗口操作中的状态串扰，并统一辅助窗口的尺寸与显示器定位策略。

## 新功能

- 终端标签支持使用平台修饰键或 Ctrl 进行多选，并按界面顺序成组拖动。
- 标签可以拖放到工作区左、右、上、下边缘创建对应方向的分屏，拖到中心区域则合并到目标工作区。
- 标签菜单支持移动到其他主窗口，以及将整个窗口的终端组并入另一窗口。
- 多分屏工作区为单个窗格提供拖拽入口，可重新编排窗格位置。
- 新增统一的成功、提示、警告和错误通知，覆盖连接保存、连接分组、设置、代理、FinalShell 导入、托管密钥及辅助窗口打开失败等操作。

## 改进与修复

- 将会话选择、连接分组、同步、删除、传输、SFTP、快速命令、托管密钥和更新器模态框迁移到窗口级管理器，避免一个窗口的模态框状态影响其他窗口。
- 统一连接管理器、设置、连接操作、SSH 编辑器和 SFTP 编辑器的窗口尺寸、居中与多显示器回退策略。
- 改进标签拖拽阈值、跨窗口命中区域、屏幕坐标换算、源窗口清理和拖拽提示，降低误触与落点不明确的问题。
- 修复跨窗口标签组接收后活动标签、分屏布局和终端当前目录可能不同步的问题。
- 连接、密钥和设置操作完成后会在所属工作区或辅助窗口显示明确结果，窗口即将关闭时也不会丢失反馈。

## 行为与界面变化

- 标签拖动超过阈值后才进入正式拖拽；多选状态在取消一次拖拽后仍会保留，便于重新选择落点。
- 将标签拖到目标窗口终端区域会合并，拖到当前工作区边缘会创建分屏；跨窗口操作完成后，空的源窗口会按现有窗口策略关闭。
- 辅助窗口优先相对当前活动工作区居中；无法取得活动显示器时回退到主显示器。
- 保存、删除、导入和连接等用户操作现在使用统一通知呈现最终结果，长时间运行状态仍保留在原有进度或状态界面。

## 配置与数据兼容性

- 配置、会话、同步协议、托管密钥和 SFTP 传输记录格式保持兼容，不需要迁移。
- 本次仅调整窗口运行状态、终端工作区编排和用户反馈路径，不新增持久化字段。
- 可直接回退到 v1.5.2；由 v1.5.3 创建或修改的现有配置与会话仍可读取。

## 升级说明

Windows、macOS 和 Linux 用户可以直接覆盖安装，无需备份或执行额外迁移。升级后已打开的旧进程需要完全退出并重新启动，才能使用新的窗口级模态框和标签拖拽行为。

## 破坏性变更与已知问题

- 无配置、数据或同步协议破坏性变更。
- 多窗口拖拽依赖操作系统窗口坐标与 GPUI 拖放事件；本次按发布要求未执行 Windows、macOS 或 Linux 手工验收。
- 按发布要求跳过所有测试、静态检查和本地 release 构建，因此本版本不声明这些质量门禁通过。GitHub 标签发布流程仍会执行其自身的发布资料校验和多平台 release 构建。
