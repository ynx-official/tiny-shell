# TinyShell v1.1.11

> 发布日期：2026-07-30

## 版本概述

本版本正式交付在线更新检查的多源兜底能力，并修复上一标签因发布日志详情引用缺失而未能生成安装包的问题。更新器优先使用随 Release 发布的稳定清单，在 GitHub API 限流或临时故障时自动切换到发布页面，同时保留 SHA-256 完整性校验。

## 改进与修复

- 优先读取 `update-manifest.json` 获取版本、资产地址、精确大小和 SHA-256，正常更新检查不再消耗 GitHub 未认证 API 配额。
- 兼容没有清单的旧发布：清单缺失时使用 GitHub Releases API。
- API 返回 403、429、服务端错误、连接失败或超时时，通过最新发布跳转和资产页面安全获取版本及校验信息。
- 严格校验发布标签、下载域名、资产路径及同一资产条目中的 SHA-256，拒绝摘要缺失、非法或跨版本资产。
- API 错误保留响应正文和限流重置时间，更新检查失败不再写入上次成功检查时间。
- 补齐 `CHANGELOG.md` 的版本详情引用，满足发布资料一致性门禁。

## 行为与界面变化

- 更新检查和安装入口保持不变。
- GitHub API 配额耗尽或临时不可用时，应用自动使用发布页面兜底，不再直接因 403 中断。
- 成功检查后继续按原配置记录时间；失败后应用重启可重新尝试。
- 本版本没有新增设置项或用户可见文案。

## 配置与数据兼容性

- 配置、连接、密钥、同步、SFTP、会话和快捷键数据格式均未变化，无需迁移。
- Windows 安装版与便携版、macOS 安装版与便携版、Linux 发布包继续使用原有资产选择规则。
- 更新清单仅作为 GitHub Release 资产，不写入用户本地配置。
- 可以回退到 `v1.1.9`；`v1.1.10` 未生成可安装产物，不作为可回退版本。

## 升级说明

可以从 `v1.1.9` 或更早版本直接覆盖安装，无需修改配置。发布流水线会为 `v1.1.11` 生成并上传 `update-manifest.json`，后续版本优先通过该清单检查更新。

## 破坏性变更与已知问题

- 本版本没有破坏性配置或数据变更。
- `v1.1.10` 标签已创建，但发布资料校验失败，因此没有生成应用安装包、便携包或更新清单；该标签不会移动或复用。
- HTML 解析仅作为旧发布或 API 不可用时的最终兜底；如果 GitHub 同时调整发布页面结构且目标发布没有清单，兜底检查仍可能失败。
- 更新清单损坏、版本不匹配或 SHA-256 非法时会拒绝更新，不会静默绕过完整性校验。

## 验证结果

根据本次发布要求，未执行本地格式检查、Clippy、Rust 测试、Python 测试和 release 构建。`v1.1.10` 标签触发的 GitHub Actions 已在线运行发布工具单元测试并通过，但因缺少 `CHANGELOG.md` 详情引用而在发布资料校验阶段失败。Windows、macOS 与 Linux 的构建及其余发布验证将由 `v1.1.11` 标签触发的 GitHub Actions 执行。
