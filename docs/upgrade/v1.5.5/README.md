# TinyShell v1.5.5

> 发布日期：2026-08-15

## 版本概述

本版本接入可选的 FreeRDP 远程桌面基础，从会话配置、原生连接、画面显示到基础输入和证书确认形成完整的实验性链路；同时加固跨窗口标签转移的事务边界，并将 SFTP、窗口注册和终端辅助逻辑拆分为职责明确的模块，降低复杂工作流中的状态丢失与安全风险。

## 新功能

- 连接配置新增 RDP 会话类型，支持保存 Windows 远程桌面主机、端口、用户和密码，并使用 `rdp://` 地址导入导出。
- 新增 FreeRDP 3.x 原生桥接、Tokio 后端生命周期和 latest-frame mailbox，可消费 BGRA 画面并在 GPUI 工作区显示最新远程桌面帧。
- 远程桌面支持基础键盘、鼠标按键、移动、滚轮输入和本地剪贴板文本粘贴，输入坐标会按等比缩放后的实际画面区域映射。
- RDP 非主动断开后最多自动重试三次，并使用 0.5 秒、1 秒和 1.5 秒退避；成功连接后重置重试计数。
- 未知或变化的服务器证书会显示主机、端口和指纹，用户可选择本次信任、当前进程内始终信任该指纹或拒绝。

## 改进与修复

- 跨窗口标签转移新增精确载荷校验、目标冲突预检、批量路由原子交接和失败回滚，避免终端、SFTP handle、系统信息页或活动标签状态丢失。
- 多组选中标签拖到边缘分屏时保留独立标签组；新窗口批量分离和已有窗口接收使用同一事务路径。
- 将跨窗口转移模型及窗格布局算法迁移到独立模块，并将窗口注册、拖拽悬停、终端路径解析和滚动条适配从应用根模块中拆分。
- 将 SFTP 命令队列、连接认证、远程文件系统、传输、远程命令、本地归档和临时目录生命周期拆分为独立模块，保留现有 UI 与运行时接口。
- SFTP 控制队列区分可靠生命周期命令与可合并的暂停/恢复请求，队列满载时优先保留关闭等高优先级控制。
- 远程归档和删除命令统一进行 shell 参数引用并使用 `--` 终止选项解析；本地 ZIP/TAR 解压拒绝目录穿越，临时文件名会移除路径分隔符。
- 在线文本编辑集中处理版本校验和原子替换保存，上传、下载、暂停、恢复、取消和打包下载的状态收尾路径更加一致。

## 行为与界面变化

- SSH 编辑器可选择 SSH 或 RDP 连接类型；现有连接未保存类型时继续显示并运行成 SSH。
- RDP 画面使用等比包含方式显示，字母箱留白区域不会发送鼠标事件；远端分辨率仍采用服务器协商结果。
- RDP 证书“始终信任”目前只在当前进程内按主机、端口和指纹保存，应用重启后需要重新确认。
- 跨窗口批量移动在任何目标冲突、路由交接或窗口创建失败时会整体恢复到源窗口，不再留下部分成功状态。

## 配置与数据兼容性

- `Session` 和 v3 同步会话新增带默认值的 `connection_type` 字段；旧配置和旧同步数据缺少该字段时自动按 SSH 读取，无需迁移。
- v1.5.5 创建的 SSH 会话仍可由旧版本读取；包含 RDP 类型的新会话在回退旧版本前建议备份配置，旧版本不理解该新增枚举值时可能无法读取对应会话或同步数据。
- SFTP 传输记录、托管密钥、连接分组和其他配置格式未发生破坏性变化。

## 升级说明

Windows、macOS 和 Linux 用户可以直接覆盖安装，现有 SSH、SFTP 和同步配置无需转换。升级前如计划创建 RDP 会话，建议先备份配置，以便需要回退到 v1.5.3 时恢复。

官方 GitHub Release 安装包使用默认 Cargo 特性构建，不链接 FreeRDP 原生库，因此安装包中的 RDP 会话会提示原生后端未接入。需要实际使用远程桌面时，必须在目标平台安装 FreeRDP 3.x 头文件与动态库，并从源码使用 `cargo run --features freerdp` 或对应 release 构建命令；非默认库路径和名称可通过 `TINY_SHELL_FREERDP_INCLUDE_DIR`、`TINY_SHELL_FREERDP_LIB_DIR` 与 `TINY_SHELL_FREERDP_LIBS` 指定。

## 破坏性变更与已知问题

- 无旧 SSH 配置、SFTP 记录或同步协议破坏性变更；旧版本对新增 RDP 枚举值的读取能力不保证，回退前请移除 RDP 会话或恢复备份。
- 官方安装包未启用 `freerdp` 特性，FreeRDP 原生后端未随本版本安装包交付。
- RDP 服务端到本地的剪贴板同步、DISP 动态分辨率和持久 GPU 纹理原位更新尚未实现；当前仅支持将本地文本粘贴到远端。
- 进程内“始终信任”证书不会写入配置文件；UI 不可用、窗口关闭或等待 60 秒超时时默认拒绝证书。
- 按发布要求未执行本轮本地测试、静态检查、release 构建或 Windows/macOS/Linux 手工验收。GitHub 标签发布流程仍会执行其发布资料校验和默认特性的多平台 release 构建。
